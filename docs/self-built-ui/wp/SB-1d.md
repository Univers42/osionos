## Interfaces

- `type SystemDocKind = "settings" | "components" | "presets"`.
- `interface SystemDoc { schemaVersion: 1; kind: SystemDocKind; id: string; version: number; title: string; blocks: Block[] }`. The `id` matches `^[a-z0-9_-]{1,64}$` and equals the file's basename; `version` is a positive integer.
- `schema.generated.json`, sorted keys:
  - `$comment`: "Generated by scripts/build-system-doc-schema.mjs. Do not edit.";
  - `schemaVersion`: 1;
  - `kinds`;
  - `blockTypes`: sorted `KNOWN_BLOCK_TYPES`;
  - `blockFields`: sorted union of `MARKDOWN_KEYS`, `OVERLAY_KEYS` and `KNOWN_LOSSY_KEYS` (`src/features/page-file/model/pageFileCodec.ts`). Its self-check already proves that union is every `Block` field, so reuse it and write no new parser;
  - `runtimeFields`: `["placeholderText"]`;
  - `styleScales`: `STYLE_SCALES`;
  - `limits`: `{ maxDepth: 12, maxBlocks: 2000, maxBytes: 524288 }`. Caveat: these limits are a guess sized for the largest settings page today (Permissions, about 300 blocks once rebuilt). Raise them when a shipped page hits them; never trim a page to fit.
- `parseSystemDoc(raw: unknown, mode: "strict" | "lenient"): { ok: true; doc: SystemDoc; unknown: string[] } | { ok: false; errors: string[] }`.
  - Both modes reject a wrong envelope (kind, id, version, title, `blocks` not an array), a block without a string `id` and `type`, duplicate ids, and anything over a limit.
  - **strict** (CI and the future bridge check) also rejects an unknown block type, an unknown field, and a `style` value that is off its scale. Each error names the block id and the key.
  - **lenient** (the app's loader) keeps those and lists them in `unknown` as `"<blockId>.type"`, `"<blockId>.<field>"` or `"<blockId>.style.<key>"`. A newer app's document must survive an older app (design §10).
- `normalizeSystemBlocks(blocks: readonly Block[]): Block[]` drops `runtimeFields`, `undefined` values and empty `children` arrays, recursively. It never invents a value.
- `serializeSystemDoc(doc: SystemDoc): string` = recursively key-sorted `JSON.stringify(…, null, 2)` plus `"\n"`, after `normalizeSystemBlocks`. Arrays keep their order.
- `loadSystemDoc(kind: SystemDocKind, id: string): Promise<SystemDoc | null>` uses `import.meta.glob("/src/system-docs/*/*.json", { import: "default" })` (lazy, so each file is its own chunk, like `widgets/admin-space/model/discoveredSections.ts:17`). It parses leniently once and caches the promise by `kind/id`. A missing file or a parse failure returns `null` and `console.warn`s once with the errors; it never throws into React.
- `isKnownBlockType(type: string): boolean`.
- `UnsupportedBlock({ block })`: an inert box reading `Unsupported block · <type>` in `--osio-fg-muted` on `--osio-bg-subtle` (existing tokens), `role="note"`, keeping the block's `data-block-id`. No editing, but the block stays in the tree, so save keeps it.

## Rules

1. Unknown types: in `BlockEditor`, after the registry lookup, `if (!isKnownBlockType(block.type)) return <UnsupportedBlock block={block} />`. In `ReadOnlyBlock`, the same check returns `null`. Today an unknown type falls into the default case and renders as a paragraph. That default stays for every known type.
2. The schema file is generated. `node … scripts/build-system-doc-schema.mjs --check` exits 1 with `system-docs schema is stale: run npm run system-docs:schema` when the committed file differs. It runs in `quality` right after `bash scripts/check-built-with-blocks.sh`. The script imports TS through `node --experimental-strip-types --experimental-loader ./tests/canvas/ts-extension-loader.mjs`, as `test-bench` does.
3. The fixpoint test is the gate on the files. For each `src/system-docs/*/*.json`: `parseSystemDoc(JSON.parse(text), "strict").ok`, and `serializeSystemDoc(doc) === text` byte for byte. On a mismatch it prints the first differing line.
4. No runtime CSS, no new token, no new dependency.
