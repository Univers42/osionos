## Why
A profile today is a jsonb blob on `osionos_bridge_identities.profile` (`models/osionos-chat-migration.sql:10`)
written read-modify-write by the bridge (`apps/osionos/app/scripts/bridge-profile.mjs:120-134,182-206`):
two concurrent edits lose one. The people directory is a view recomputing `to_tsvector` per row
over a three-way join (`models/osionos-people-directory-migration.sql:45-63`, its own
"ponytail" note says so); every search is a sequential scan. Usernames have two homes:
`public.users.username` (the gateway enforces `^\w[\w.-]{2,31}$`,
`apps/opposite-osiris/scripts/auth/identity.mjs:11`) and `osionos_bridge_identities.username`
(the bridge accepts any 48 characters). No table holds settings, username history or deletion
requests.

## Scope cut (YAGNI, decided)
In: `osionos_profiles`, `osionos_user_settings`, `osionos_username_history`,
`osionos_account_deletion_requests`, the directory view rebuilt over profiles.
Out, each lands with the package that first reads it: emails (P3-1), follows (P2-3),
presence (P0-5), `readme_page_id` (P2-1), avatars in storage (P0-6 — avatar columns exist here but
stay NULL; the view keeps the legacy fallback until P0-6 migrates them).

## Tables (every one: FK `user_id → auth.users(id) ON DELETE CASCADE` unless stated,
`COMMENT ... 'osionos:account-plane'`, RLS on, `REVOKE ALL ... FROM PUBLIC, anon, authenticated`,
`GRANT ALL ... TO service_role` + a `service_role` FOR ALL policy, the realtime trigger dropped
— grobase's CREATE TABLE hook would broadcast every row, as P0-1 found)

1. **`osionos_profiles`** — PK `user_id`.
   `display_name TEXT NOT NULL` (1–100, single line), `username TEXT` (NULL allowed; CHECK
   `^[A-Za-z0-9_][A-Za-z0-9_.-]{2,31}$` — the gateway's rule — and `NOT osionos_username_reserved(username)`;
   unique index on `lower(username)`), `pronouns` (≤ 40), `headline` (≤ 200), `bio` (≤ 2000),
   `location` (≤ 120), `company` (≤ 100), `website` (`^https?://\S{1,250}$`), `links TEXT[]`
   (≤ 4 entries, each `^https://\S{1,250}$`), `timezone` (≤ 64, `^[A-Za-z]+(/[A-Za-z0-9_+-]+){0,2}$`;
   real-zone validity is the bridge's job), `orcid` (`^\d{4}-\d{4}-\d{4}-\d{3}[\dX]$` AND the ISO 7064
   MOD 11-2 check digit, an IMMUTABLE function), `patreon` (`^[A-Za-z0-9_-]{1,64}$`),
   `avatar_url`, `banner_url` (≤ 512, `^(https://|/)`, never `data:`), `directory_opt_out BOOLEAN NOT NULL DEFAULT false`,
   `version INTEGER NOT NULL DEFAULT 1`, `created_at`, `updated_at`.
   Single-line fields refuse control characters; `bio` allows `\n` only.
   `search_doc tsvector GENERATED ALWAYS AS (to_tsvector('simple'::regconfig, coalesce(display_name,'') || ' ' || coalesce(username,'') || ' ' || coalesce(headline,'') || ' ' || coalesce(bio,''))) STORED`
   (`concat_ws` is STABLE and is refused in a generated column).
   Indexes: GIN `search_doc`; GIN trigram (`gin_trgm_ops`; `pg_trgm` is created by
   `models/osionos-social-migration.sql:11` — qualify the opclass with the extension's schema)
   on `display_name`, `username`, `headline`; btree `(display_name, user_id)` for the no-query listing.
   A BEFORE UPDATE trigger sets `version = OLD.version + 1`, `updated_at = now()` (the bridge's
   If-Match is `PATCH ...&version=eq.N`; zero rows → 412).
   Role grants: SELECT on every column (all are public profile fields);
   UPDATE on `display_name, username, pronouns, headline, bio, location, company, website, links,
   timezone, orcid, patreon, directory_opt_out` only (NOT the avatar/banner, `version`, timestamps,
   `user_id`); no INSERT, no DELETE. Policies: owner SELECT and owner UPDATE (`USING` and
   `WITH CHECK` `user_id = (SELECT public.osionos_account_uid())`). Other people's profiles are
   read through the directory view by the bridge's service role (ADR 0001 "not decided here").
2. **`osionos_user_settings`** — PK `(user_id, section)`; `section TEXT` (`^[a-z][a-z0-9_-]{0,31}$`),
   `value JSONB NOT NULL` (an object, `pg_column_size(value) <= 16384`), `version`, `updated_at`.
   A row per section so writes to two sections never contend. Function
   `osionos_user_settings_merge(p_section text, p_patch jsonb) RETURNS jsonb`, **SECURITY INVOKER**,
   `SET search_path = pg_catalog, public`: `INSERT ... ON CONFLICT (user_id, section) DO UPDATE SET value = jsonb_strip_nulls(osionos_user_settings.value || EXCLUDED.value)`
   with `user_id = public.osionos_account_uid()` (NULL → raise 42501) — a shallow merge in one
   statement, so concurrent PATCHes to one section both land; a `null` deletes a key.
   Role: SELECT `section, value, version, updated_at`; INSERT/UPDATE `(user_id, section, value)`
   (the merge runs as the role, so it needs them; RLS `WITH CHECK` owner holds); EXECUTE the merge.
3. **`osionos_username_history`** — `id UUID PK DEFAULT gen_random_uuid()`, `user_id UUID NULL
   REFERENCES auth.users ON DELETE SET NULL` (a deleted user's names stay held), `username TEXT
   NOT NULL`, `changed_at`, `released_at TIMESTAMPTZ NOT NULL` (= `changed_at + 90 days`), index
   `(lower(username), released_at)`. An AFTER UPDATE OF username trigger on profiles inserts the
   old name. A BEFORE INSERT OR UPDATE OF username trigger refuses (23505, a message naming the
   hold) a name held by anyone else: a history row with the same `lower(username)`, `released_at
   > now()` and `user_id IS DISTINCT FROM NEW.user_id`. The owner may reclaim their own old name.
   Role: SELECT `username, changed_at, released_at` on own rows; nothing else.
4. **`osionos_account_deletion_requests`** — PK `user_id`; `requested_at DEFAULT now()`,
   `scheduled_for TIMESTAMPTZ NOT NULL DEFAULT now() + interval '14 days'`, CHECK
   `scheduled_for >= requested_at + interval '14 days'` (a client cannot shorten the grace),
   `successor_user_id UUID NULL REFERENCES auth.users ON DELETE SET NULL`, CHECK
   `successor_user_id IS DISTINCT FROM user_id`. Cancel = DELETE (the audit table records it).
   Role: SELECT all; INSERT `(user_id, successor_user_id)`; DELETE; owner policies for each.
   The executor (P5-6) runs as service_role.

`osionos_username_reserved(text)` — IMMUTABLE, a short inline list (`admin, administrator, api,
app, auth, help, login, logout, me, new, osionos, p, root, settings, signup, support, system, u,
www`), case-insensitive. Every new function: `REVOKE EXECUTE ... FROM PUBLIC`, then grant only
what is listed; check `h` (`secdef_exec`) must stay 0.

## Keeping every user in the directory
The directory exists so that people who never opened osionos still appear
(`osionos-people-directory-migration.sql:1-12`). So every `public.users` row with an `auth.users`
row gets a profile:
- **Backfill** (every boot, `INSERT ... SELECT ... ON CONFLICT (user_id) DO NOTHING`, so user edits
  are never overwritten): the source set is `(public.users.id ∪ osionos_bridge_identities.user_id) ∩ auth.users.id`.
  `display_name` = the old view's chain (`up.display_name`, `bi.display_name`, `u.name`,
  `u.username`, `'Member'`, trimmed, cut to 100). `headline`/`bio`/`location` from
  `bi.profile` when they pass the CHECKs, else NULL. `directory_opt_out` from `bi`.
  **Username:** candidates `u.username` (rank 0) and `bi.username` (rank 1); a candidate is
  dropped if it fails the regex, is reserved, is held in history, or is already taken by another
  profile; among the rest, per `lower(name)` the winner is the lowest (rank, `u.created_at`,
  `user_id`); every loser gets NULL. One NOTICE per category with a COUNT (never the names).
- **New users:** an AFTER INSERT trigger on `public.users` creates the profile, `SECURITY DEFINER`
  (the inserter may be GoTrue's `handle_new_user` or the gateway, neither granted on
  `osionos_profiles`), `SET search_path = pg_catalog, public`, and it **never raises**: any error
  → `RAISE WARNING` and `RETURN NEW` (registration must not fail; the next boot's backfill heals the
  gap). No `auth.users` row → no profile, WARNING.
- **Legacy writes** (the bridge until P1-2 switches): an AFTER INSERT OR UPDATE OF `profile, username,
  directory_opt_out` trigger on `osionos_bridge_identities` copies `headline, bio, location,
  directory_opt_out` and a valid, free `username` to the profile; an invalid value keeps the old
  one with a WARNING. It never touches `display_name` (identities rewrites it at sign-in) and never
  raises. `last_seen_at`-only updates do not fire it.

## Directory view
`DROP VIEW` + `CREATE VIEW public.osionos_people_directory WITH (security_invoker = true)` over
`osionos_profiles p LEFT JOIN user_profiles up LEFT JOIN osionos_bridge_identities bi`, columns in
the **old order** (`user_id, display_name, username, profile, last_seen_at, directory_opt_out,
search_doc` — the old bridge image selects them) plus `headline` at the end. `display_name`,
`username`, `search_doc`, `headline` are the profile's own columns (no COALESCE, so the indexes
apply). `profile` = `jsonb_build_object('avatar', COALESCE(p.avatar_url, up.avatar_url, bi.profile->>'avatar'), 'headline', COALESCE(p.headline,''))`.
`GRANT SELECT ... TO service_role` only. `models/osionos-people-directory-migration.sql` becomes a
tombstone (a header saying what replaced it and why; no SQL), so no file re-creates the old view.

## Checks (append to `scripts/verify/models-grants/account-checks.sql`; k5/k6 stay LAST)
- k3 array gains the four tables; k4 gains every index above (exact key columns).
- `p1_role_column_acl` = 0: the role's (table, column, privilege) set from
  `information_schema.column_privileges` + `has_table_privilege` for DELETE/TRUNCATE/TRIGGER differs
  from the expected VALUES list above (one row covering all four tables).
- `p1_isolation_forged` = 0: in a rolled-back txn with users A and B, one row each in every table,
  as the role with A's claims, the count of B's rows readable in any table plus B's rows changed
  by `UPDATE osionos_profiles SET bio='x'`, by `osionos_user_settings_merge` for B (impossible —
  the function keys on the caller), and by `DELETE FROM osionos_account_deletion_requests`.
- `p1_isolation_own` = 4 (A sees exactly its own row in each table).
- `p1_hold` = 0: B cannot take A's released-in-the-future old name; A can reclaim it.
- `p1_never_raises` = 0: an `INSERT INTO public.users` whose username collides with a profile,
  and one with no `auth.users` row, both succeed.
- `check_standalone` gains a row per new table: realtime triggers = 0, anon/authenticated privs = 0.
- After `models-first-run.sh` pass 2: the `public.users` trigger still exists (grobase's boot does
  not drop it — this was preflight #8, unknown until now).
