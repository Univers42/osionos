## Why
With P0-4, a bridge that holds a service key answers 503 to every token check until it can load
`public.osionos_sessions`. Two places start such a bridge without that table or the env it needs:
- **Desktop.** `apps/osionos-electron/native/firstrun.mjs` applies `MIGRATIONS` (`:34-48`) only on a
  fresh install, and re-runs `auth-session-cutoffs.sql` every boot after GoTrue
  (`applyAuthSessionCutoffs`, `:113-120`, called from `native/supervisor.mjs:85-86`). The account
  foundation references `auth.users` (GoTrue-owned), so it belongs in that after-GoTrue step, not in
  `MIGRATIONS`. The P0-1 file's header says what the desktop lacks (`osionos_feed_shares` never
  exists there) — read it; the step must succeed on a desktop database.
- **Compose.** The bridge service in `docker-compose.yml` (`:79-153`) has no Redis env, although
  `mini-baas-redis:6379` is reachable on the `mini-baas` network (the gateway uses it, `:546`). The
  lean overlay `docker-compose.local.yml` takes the bridge off that network (`:24-29`).

## Changes
1. `firstrun.mjs`: the after-GoTrue step applies `auth-session-cutoffs.sql` **then**
   `osionos-account-foundation-migration.sql`, every boot, in one function (rename it for what it
   now does and update its caller and comment). If the foundation needs objects the desktop lacks,
   make the foundation file tolerate their absence **only** where its header already says so —
   otherwise stop and report; do not weaken the migration for the server.
2. Make sure the desktop image ships the foundation file wherever `cfg.migrationsDir` points
   (check how `auth-session-cutoffs.sql` gets there and do the same).
3. `docker-compose.yml`, bridge service `environment:` — `OSIONOS_BRIDGE_REDIS_URL:
   ${OSIONOS_BRIDGE_REDIS_URL:-redis://mini-baas-redis:6379}` and `OSIONOS_BRIDGE_CLIENT_IP_HEADER:
   ${OSIONOS_BRIDGE_CLIENT_IP_HEADER:-x-real-ip}` (nginx sets X-Real-IP,
   `infrastructure/tls/nginx.conf:44`). `docker-compose.local.yml`: `OSIONOS_BRIDGE_REDIS_URL: ""`.
   Add both names, with comments, to the env example file the bridge's other variables are
   documented in (names only, never values).
