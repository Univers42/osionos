## Decisions (D-P1-6, 2026-10-22) — binding

The orchestrator wrote this spec while every free model was refused. The drafter S-P1-6 was stopped before it wrote anything. Inputs: `target/specs/R-SETTINGS.md` §4, §23, §25 (spot-checked 5/5), the contracts in `wp/P1-2a.md` (profile routes), `wp/P1-2b.md` (sudo, username, deletion) and `wp/P0-6.md` (avatar), and the code below, re-opened on 1d1702d0.

1. **The server profile is the one source.** `GET`/`PATCH /api/account/profile` (P1-2a) replace three things:
   - `AccountSettings.profile`, which lives in localStorage only (`src/store/settings/types.ts:15-19`);
   - the dead `PATCH /api/profile/me` client `patchProfileMe`, which has no caller (`src/shared/social/directoryApi.ts:60-62`);
   - the emoji avatar picker, which never persisted (`src/features/settings/profile/ProfilePanel.tsx:155-167`).

   All three are deleted, not kept beside the new path.
2. **Save is explicit.** One "Save profile" button, enabled only when the draft differs, busy while saving. A 412 `version_mismatch` shows "This profile changed in another tab or device", with **Reload** (take the server row) and **Keep mine** (re-send with the new version). It never overwrites silently. Autosave and If-Match fight each other, so there is no autosave here.
3. **Client checks mirror the database, they never replace it.** `profileFields.ts` checks the P1-1 rules (`wp/P1-1.md:30-41`) so the user sees the error before saving. A 422 `invalid_field` from the server is still shown on the field it names.
4. **One sudo prompt for the whole app.** `SudoPrompt` mounts once (in `SettingsView`), listens to `onSudoRequired` (`src/shared/api/sudoRequired.ts:44`), runs the emailed-code flow (`POST /api/account/sudo/email`, then `/verify`, `wp/P1-2b.md:113-140`) and then lets the user retry the refused action. No panel handles a 403 itself.
5. **Delete account sits behind `osio.account.delete` (default off), with a grace period.**
   - The gesture is: type your **username**, then sudo, then `POST /api/account/deletion`.
   - The user stays signed in. Today's code logs out (`ProfilePanel.tsx:145-147`); that goes.
   - While a request exists, the danger zone shows "Your account will be deleted on <date>" with **Cancel deletion** (`DELETE /api/account/deletion`).
   - With the flag off, the row is hidden, not disabled.
6. **What does not exist says so or goes.** The fake passkey credential (`ProfilePanel.tsx:132`) becomes "Passkeys aren't available on this server yet". Removed outright:
   - the hard-coded email fallback (`:111`);
   - the "osionos Faces" line (`:182`);
   - the dead "Load more devices" (`:197`);
   - the unbacked "Support access" toggle (`:191`).

   P3-1, P3-2 and P3-3 own the security flows themselves (password, 2FA, sessions); P1-6 only stops them from lying.
7. **The profile page shows what the editor saves.** `useProfile` follows `GET /api/profile/:userId` with `GET /api/users/:username` when a username exists, and merges the allowlisted public fields. P2-1 replaces this with the README page. Your own page gets **Edit profile**, which deep-links to `profile#public-profile`.
8. **Banner comes last (P1-6-d).** It reuses P0-6's validate, strip and store pipeline in `bridge-avatar.mjs`, with one size; it is not a second upload module.
9. **Order:**
   - a and c in parallel (disjoint OWNS), dispatched after P1-2a and P2-5-a are merged;
   - b after a;
   - d after a and P0-6.

## Contract

### P1-6-a — the public profile editor

1. **`src/shared/api/accountProfileApi.ts`** (new: no client for `/api/account/*` exists) exports:
   - `fetchAccountProfile()`, which returns `{ profile, version }`;
   - `saveAccountProfile(patch, version)`, which sends `If-Match: "<version>"`.

   **P2-4-d2 builds this file and item 2's store first (D-P2-4ds); P1-6-a extends them and creates neither.** The module calls `fetch` itself with the app-session token (`settingsJwt()`, P1-5), because the shared `api` client can neither send `If-Match` nor return the 412 body (ADR 0004). The outcome is typed:
   - `ok` (row + version);
   - `conflict` (the server's row + version, from the 412);
   - `invalid` (the field name from the 422);
   - `unavailable` (no `API_BASE`, a 404, or a 503 `account_plane_unavailable`);
   - `failed`.

   `patchProfileMe` and its `ProfilePatch` type are deleted from `directoryApi.ts` if nothing else imports them.
2. **`src/store/settings/useAccountProfileStore.ts`** (new: no store holds the server profile) has state `{ status, profile, version, error }` and actions `hydrate()` and `save(patch)`. It is exported from the settings barrel. On `conflict` it keeps the draft and exposes the server row.
3. **`src/features/settings/profile/profileFields.ts`** (new, pure) exports:
   - one validator per field, mirroring P1-1: display name 1–100 single line; pronouns ≤40; headline ≤200; bio ≤2000 with newlines allowed; location ≤120; company ≤100; website `https?://`; links ≤4, each `https://`; timezone from `Intl.supportedValuesOf('timeZone')`; patreon `^[A-Za-z0-9_-]{1,64}$`; orcid `^\d{4}-\d{4}-\d{4}-\d{3}[\dX]$` **and** the ISO 7064 MOD 11-2 check digit;
   - `diffProfile(base, draft)`, which returns only the changed keys.
4. **`src/features/settings/profile/PublicProfileSection.tsx`** (new; `ProfilePanel.tsx` must stay ≤300 lines) is a `Section` with `anchor="public-profile"`, titled "Public profile":
   - **Fields:** display name, pronouns, headline, bio (textarea with a live character count), location, company, website, up to four links (add/remove rows), local time (a timezone select showing the current time there), ORCID, Patreon. Each has a visible label, its rule as hint text, and its error under it (`aria-describedby`, `aria-invalid`).
   - **Avatar:** `ImageAvatarUpload` plus a "Remove photo" button (`DELETE /api/profile/avatar`, P0-6), which asks first through `ConfirmModal`.
   - **States:** `PanelStatus` around everything; an `EmptyState` with a short explanation when the server says `unavailable` (offline build). The section never shows a form that cannot save.
   - **Footer:** a "Who can see this" line: "Everyone in your workspaces and the people directory, unless you hide your profile in Privacy."
5. **`ProfilePanel.tsx`.** The "Account" section (`:152-183`) is replaced by `<PublicProfileSection>`. The emoji picker, the preferred-name autosave and their state go.
6. **`sections.ts`.** The `profile` section's first anchor becomes `{ id: 'public-profile', label: 'Public profile', keywords: ['name','pronouns','bio','website','links','company','location','orcid','patreon','avatar','photo'] }`. It replaces `account`. Grep callers of the `account` anchor, and update the palette tests that name it.
7. **`types.ts`, `defaults.ts`, `useAccountSettingsStore.ts`.** Remove `AccountSettings.profile` and every reader of it. No other change.

### P1-6-b — account security that tells the truth, sudo, username, danger zone (after a)

1. **`src/shared/api/accountSecurityApi.ts`** (new) calls each P1-2b route and returns the same typed outcome shape as in a:
   - `requestSudoCode()` → 202 `{ sentTo }`;
   - `verifySudoCode(code)` → 204;
   - `sudoStatus()`;
   - `changeUsername(username)` → 409 `username_unavailable` / 422 `invalid_username`;
   - `requestDeletion()`, `deletionStatus()`, `cancelDeletion()`.
2. **`src/features/settings/ui/sudo/SudoPrompt.tsx`** (new) mounts once in `src/features/settings/ui/SettingsView.tsx`.
   - On `onSudoRequired` it opens a modal: "Confirm it's you". The button "Email me a code" shows the masked address; then a 6-digit input (`inputMode="numeric"`, `autocomplete="one-time-code"`, labelled).
   - Every server code gets one sentence: `code_invalid`, `code_expired`, `code_locked`, `sudo_unavailable`, and a 429 that says when to retry.
   - On 204 it closes and fires a `retry` callback so the panel can re-run the refused action. The panel's button says "Try again"; nothing re-sends by itself.
3. **`src/features/settings/ui/danger/DangerZone.tsx`** (new): a bordered `--osio-danger*` section ("Danger zone") holding `SettingRow danger` children. It is used by the account panel, and later by P3-5 and P5-6.
4. **`ProfilePanel.tsx` security, support and devices:**
   - **Username:** a new row in "Account security" showing `@username`, with "Change" opening a modal with live format validation (P1-1's regex). The submit is sudo-gated by the server.
   - **Passkeys:** remove the fake credential; with no options from the server, say "Passkeys aren't available on this server yet".
   - **Removed:** the email fallback literal, the "osionos Faces" line, "Load more devices", and the "Support access" row together with its `SupportDurationModal` usage.
   - **Delete:** "Delete my account" moves into `DangerZone`, behind `isAccountDeleteEnabled()`. That is a new `osio.account.delete` flag in `src/shared/config/featureFlags.ts`, default off, written like its neighbours. The gesture is `TypedConfirmModal` with `confirmText` = the username (or the email when there is none), then `requestDeletion()`. A sudo refusal opens `SudoPrompt`. The user stays signed in.
   - **Grace banner:** while `deletionStatus()` returns a row, the danger zone shows "Your account will be deleted on <scheduledFor>" and **Cancel deletion**.
5. **`sections.ts`.** The `profile` section gains the anchor `{ id: 'danger', label: 'Delete account', keywords: ['delete','close','remove account'] }` only when the flag is on. Otherwise the palette never offers a hidden row.

### P1-6-c — the profile page shows the saved profile; "Edit profile" on your own (parallel with a)

1. **`useProfile.ts`.** When `/api/profile/:userId` returns a `username`, also read `GET /api/users/:username` (P1-2a item 3) and merge **only** these fields into `MemberProfile`, typed as optional: `pronouns, headline, bio, location, company, website, links, timezone, orcid, patreon, avatarUrl, bannerUrl`. A failed second read leaves the first result as it is, with no error state.

   `Caveat:` two reads per profile view until P2-1 serves one projection. The 60 s refresh (`REFRESH_MS`) repeats both.
2. **`ProfileView.tsx`:**
   - pronouns next to the name;
   - company, location and **local time** (computed from `timezone`, refreshed each minute);
   - website and links as `<a rel="noopener noreferrer me" target="_blank">` showing only the host;
   - ORCID as `https://orcid.org/<id>`;
   - Patreon as `https://www.patreon.com/<handle>`.

   A field that is absent renders nothing (no empty labels). The presence dot uses `--osio-success` instead of `bg-green-500`.
3. **`profileChrome.tsx`.** On your own profile, `ProfileActions` renders one **Edit profile** button, which calls `openSettings('profile', 'public-profile')` (`src/features/settings/model/settingsNav.ts:53`), instead of `null`.
4. **Security edge.** The page renders only the allowlisted fields above. It never calls `/api/account/*` for someone else, and a reduced card (opted out or blocked, P1-2a) shows only the name and avatar.

### P1-6-d — profile banner (after a and P0-6)

1. **`scripts/bridge-avatar.mjs`** gains `POST`/`DELETE /api/profile/banner`, reusing that module's sniff, strip, store and `asService` PATCH path:
   - one variant 1500×500, webp or jpeg, ≤400 KB;
   - stored as `<sha>-banner.<ext>`;
   - sets `banner_url`;
   - rate limit 10/h.

   `GET /api/media/avatars/:userId/:key` accepts the `-banner` key.
2. **The client.** `PublicProfileSection` gets a banner picker that crops to 3:1 in the browser, the way `ImageAvatarUpload` downsizes (`ImageAvatarUpload.tsx:25-42`). `ProfileView` shows the banner above the header when present.
