## Contract

### P5-3-a — root SQL, validator, CRUD

1. **Table** `osionos_user_keys`, one idempotent file `models/osionos-user-keys-migration.sql` (`IF NOT EXISTS`, `DROP POLICY IF EXISTS`): `id uuid pk`, `user_id uuid not null` (FK with cascade on user deletion, matching the PAT table), `kind text not null CHECK (kind in ('ssh','gpg'))`, `title text not null CHECK (char_length(title) between 1 and 80)`, `public_key text not null CHECK (octet_length(public_key) <= 16384)`, `fingerprint text not null`, `key_type text`, `created_at`. `unique (user_id, kind, fingerprint)`. No `last_used_at` (Q7) and no private-key column. At most 50 rows per user, enforced by a BEFORE INSERT trigger taking `pg_advisory_xact_lock(hashtext(user_id::text))` and raising on the 51st; the route maps that to 409 `key_limit`. No app-side count is the authority.
2. Grants follow the PAT table: INSERT/UPDATE/DELETE to the service role only, column-level SELECT to the account role, owner_read policy via `(SELECT public.osionos_account_uid())`, realtime trigger dropped, `COMMENT ... 'osionos:account-plane'`, `NOTIFY pgrst`. Registered in `ORDERED_LAST` (`apply-models-migrations.sh:199`) BEFORE `osionos-service-role-only-migration.sql`, so the pinned tail stays the last three. Checks `p5_keys_column_acl` and `p5_keys_row_rules` are added to `scripts/verify/models-grants/checks.sql` (and `account-checks.sql` if the PAT checks use it) and wired next to `models-grants.sh:611-612`; `check_standalone` gets a `keys=` var beside :343.
3. **Validator** `scripts/bridge-key-parse.mjs` (pure, `node:crypto`/Buffer only, <= 300 lines; no shared hashing helper is extracted). `parseSshPublicKey(text)` returns `{type, blob, fingerprint, bits?}`. It accepts exactly one line `<type> <base64> [comment]` for `ssh-ed25519` (blob exactly 32-byte key), `ecdsa-sha2-nistp256/384/521` (curve name in the blob must match the type), `ssh-rsa` (**>= 3072 bits**, computed from the modulus mpint with the leading zero byte stripped; the number 3072 is the floor, a 2048-bit key answers 400 `key_weak`), `sk-ssh-ed25519@openssh.com`. The blob must decode and its embedded type string must equal the declared type. Fingerprint = `SHA256:` + unpadded base64 of SHA-256 over the decoded blob (what `ssh-keygen -lf` prints). `parseGpgPublicKey(text)` accepts one armored `PGP PUBLIC KEY BLOCK`, checks the CRC-24 (mismatch 400 `key_invalid`), **v4 only** (v5/v6 and anything else 400 `key_unsupported`), walks EVERY top-level packet, and returns the 40-hex fingerprint (SHA-1 over `0x99 || 2-byte length || body` of the primary tag-6 packet) and the algorithm.
   - 3a. **The comment is discarded and the stored/emitted line is rebuilt** as `type + " " + base64(blob)`; the title (free text) never enters any file and the comment is never stored, returned or logged. Input containing CR, LF, NUL, U+2028 or U+0085, a second line, or an options-looking first token (`command=ssh-ed25519 AAAA`, `from="..." ssh-ed25519 ...`) answers 400 `key_invalid`.
4. **Private material is refused, never stored or echoed.** `PRIVATE KEY`, `BEGIN PGP PRIVATE`, an `openssh-key-v1` header, or a PGP secret-key (tag 5) or secret-subkey (tag 7) packet ANYWHERE in the stream (old and new length formats; partial body lengths refused; packet count and total bytes capped) answer 400 `private_key_refused` with a fixed body string. The audit row for such an attempt, if written, holds `{kind}` only. Neither body, audit rows nor console output contain any substring of the submitted text.
5. **Routes** (module `scripts/bridge-account-keys.mjs`, <= 300 lines, tabs, 42 header, mounted in `bridge-account-mounts.mjs`): `GET /api/account/keys`, `POST /api/account/keys` (`{kind, title, publicKey}`), `DELETE /api/account/keys/:id`. Every route needs a verified session; no cross-user or admin read.
6. **POST** order: session -> `rateLimit` -> `requireSudo` -> body validation -> parse -> `writeAudit` (`account.key.add`, `{kind, fingerprint}` only) -> insert -> 201 `{id, kind, title, fingerprint, keyType, createdAt}`. Rate limit: 10 adds per hour per user, key `['key-add', session.userId]`. The PAT precedent (`bridge-account-tokens.mjs:55,57,202`) is 10 per `WINDOW_MS = 60_000`, so the window does NOT match: this module defines its own 1-hour window constant (Decisions Q6). Duplicate fingerprint for the same user answers 409 `key_exists`; the same fingerprint under another user is allowed. The 409 and 404 bodies reveal nothing cross-user.
7. **Unknown fields.** The body accepts exactly `{kind, title, publicKey}`; `fingerprint`, `keyType`, `id` or any other key answers 422 and the value is audited nowhere. The fingerprint is computed only server-side.
8. **DELETE**: session -> `requireSudo` -> `writeAudit` before delete -> ONE statement `delete from osionos_user_keys where id=$1 and user_id=$2` whose row count decides 204 vs 404 (no select-then-delete). A foreign id answers the same 404 body as a random UUID.
9. **PAT refusal (corrected).** There is no `pat_route_not_allowed` middleware on this tree: `rg pat_route_not_allowed scripts src` hits only the comments at `bridge-account-tokens.mjs:20,280`. The key routes call `verifySession(bearerToken(request), config)` like `createPatRoutes` (`bridge-account-tokens.mjs:278-285`), so a PAT-shaped bearer is 401 and creates nothing. Q3 is closed.

## Findings

**F1 (blocking for c) The injection has no consumer.** `ide-sandbox/Dockerfile` installs `bash ca-certificates curl git python3 ...` (apt line 30-31) and no `openssh-client`, no `gnupg`; there is no sshd. `~/.ssh/osio_keys.pub` and `allowed_signers` do nothing, and `git log --show-signature` / `%G?` cannot verify. Spec item 14 therefore makes vigilant mode a label over "every commit is N". Q2 decides whether c is worth doing at all.

**F2 Q1 is answerable and the "signed payload" default is overbuilt.** The plane is DB-less (`ide-server.mjs`), keys live in Postgres behind the main bridge. Keys are public and user-chosen, injected only into that user's own box, so a client relay (GET own keys from the main bridge, POST them to the plane) cannot escalate anything provided the plane re-validates. No new signing channel is needed.

**F3 Delete does not reach a running box.** Item 13 syncs on ensure and on add/delete, but item 12 does not say the sync REPLACES the files. An append or an import-only sync leaves a revoked key trusted; `gpg --import` can never remove a key. Cost on failure 3.

**F4 Exec shape.** The proxy requires `WorkingDir == "/workspace"` (`create-shape.mjs:207`), allows `AttachStdin` but the existing code never uses stdin: every precedent passes content as ARGV (`ide-sandbox-spec.mjs:288,318`, base64 pieces of 96 KiB, `WRITE_PIECE_B64` :210). The "stdin/argv" wording of item 12 invites a new stdin plumbing path. Use argv + a constant `sh -c` script (precedent `buildFsOpSpec`), absolute target `/home/coder/.ssh`, which `assertRelPath` (:198-203, rejects `/` prefix) cannot express: a new builder is needed, copying the atomic temp+mv idiom, not calling `buildFsOpSpec`.

**F5 Comment and options reach the file.** Item 3 accepts `[comment]` and nothing says it is dropped. An `allowed_signers` or `authorized_keys` line is `principals options? type blob`; a comment or title containing spaces/newlines/`command=`/`from=` is the injection. Fix: never store or emit the comment; regenerate every line as `<principal> <type> <blob>` from the parsed fields; the title (80 chars, free text) never enters a file.

**F6 GPG walk.** Item 3 "walks to the primary public-key packet" and the Caveat says primary only. A secret subkey (tag 7) or secret key (tag 5) AFTER the primary passes that walk and is then stored and injected. Item 4 lists tags 5/7 but the walk contract does not scan all packets. v5/v6 keys: "accepted or refused" is not a contract.

**F7 Key limit race.** "At most 50 per user, counted in the insert path" is app code; concurrent POSTs overshoot. The rate limit (10/h) bounds it but the user asked for DB constraints. Use a BEFORE INSERT trigger with `pg_advisory_xact_lock(hashtext(user_id::text))`, or accept the overshoot as documented.

**F8 Duplicate / ownership.** `unique (user_id, kind, fingerprint)` is a DB constraint (good) and the 409 reveals nothing cross-user (good). Item 7 returns 404 for a foreign id (good); the DELETE must be one statement `delete ... where id=$1 and user_id=$2` returning the row count, not select-then-delete.

**F9 No unreviewed duplicate logic if built as stated, with two exceptions.** (i) the PAT mount/guard seams are reused (`bridge-guard.mjs:167,194,224`); (ii) item 12 must reuse the fs-op write idiom (F4) and `bridge-ide-ops` route set (`bridge-ide-ops.mjs:169`) rather than a parallel handler. A third copy of base64/fingerprint code must not appear: `ide-token.mjs` and `bridge-pat-store.mjs` already hash; use `node:crypto` directly in the parser, nothing to share.

**F10 Gates that can pass while wrong.**
- "response and audit never contain the submitted private text" passes trivially if the response is empty or the route 500s: require a positive assertion (status 400, code `private_key_refused`, audit row for the refusal exists with `fingerprint` absent).
- Fingerprint tests "vs pinned ssh-keygen" pass if the expected value is computed by the code under test; require literal constants copied from a real `ssh-keygen -lf` output, committed as fixtures with the command in a comment.
- Mutant list has no GPG mutant (CRC skipped, tag 7 not refused, fingerprint over body without `0x99`) and no sync-replace mutant (F3). A fake that returns 200 for any `fetch` would pass `models-grants` only if checks.sql is not extended (F12 below).
- `tests/canvas/ide-vigilant-badge.test.ts` "visible only for vigilantMode && connected" asserts a pure model; it cannot catch that the flag was never wired to `IdeSourceControl.tsx`: add a render test of the component.

**F11 OWNS makes parts impossible.**
- `scripts/verify/models-grants/checks.sql` (and `account-checks.sql`) are not owned; the PAT ACL/row checks live there (`checks.sql:126,239,257,306`; wired `models-grants.sh:611-612`). Without a keys equivalent the new table's grants are unchecked ("skipped is not passed").
- Spec owns `bridge-ide-ops.mjs` "the sync route only", but `POST /api/ide/keys/sync` must also be added to the `routes` Set at `bridge-ide-ops.mjs:169`; fine, same file. The route is not in `bridge-ide-sandbox.mjs`'s `ensure`, so item 13's `keys: "stale"` in the ensure reply needs `createIdeSandboxHandler` (:219) edits: owned, ok.
- `src/features/ide/model/*` needs a client function to relay keys (useIdeGit.ts is owned but is the git hook; the relay belongs in a new `ideKeys.ts` or the same file; name it).
- Item 14 puts `vigilantMode` in `bridge-preferences.mjs`: `SECTIONS` entries are per URL, only moderation has `prepare` (:43). Adding `prepare` to `/api/preferences` would change a 120/min shared endpoint for every key; the flag belongs in the existing `preferences` section with a normaliser scoped to that one key, plus the matching client store (`useUserPreferencesStore`, not owned).

**F12 Security edges that hold.** Session first, sudo on add/delete, audit-before-insert via `writeAudit` (`bridge-guard.mjs:224`, details must be a plain JSON object, `assertDetails` :204), column-level grants and owner_read via `(SELECT public.osionos_account_uid())` copy the PAT migration (`osionos-personal-access-tokens-migration.sql:75,116,120,128-143`). Rate limit key must include user id (`rateLimit(kv, parts, {limit, windowMs})` :167; PAT precedent `bridge-account-tokens.mjs:202`).

## Decisions proposed

1. **Q1 (plane or main bridge?)** The plane; `scripts/ide-server.mjs:20-21`. Use the client relay with plane-side re-validation (condition 13), not a signed payload: keys are public, user-chosen, and land only in the caller's own box.
2. **Q2 (openssh-client + gnupg in the image?)** Add `openssh-client` only (needed for git SSH signing, `ssh-keygen -Y verify`); skip `gnupg` (large, GPG verification not needed to ship). GPG keys stay stored and displayed, not injected. If the root Dockerfile change is refused, cut P5-3-c to nothing and ship a+b.
3. **Q3 (PAT middleware path list?)** There is none on this tree; rely on the app-session check in the route (401 for a PAT), condition 8.
4. **Q4 (vigilant sets `commit.gpgsign`?)** Display only. `git config` is denied by design (`ide-sandbox-spec.mjs:140-150`) and signing needs a private key we refuse to hold.
5. **Q5 (sudo on add?)** Yes on both: an added key is a credential that reaches a box, same as token creation (`bridge-account-tokens.mjs:249,272`).
6. **Q6 (50 keys, 10/h)?** Keep 50 total (cap in the DB trigger) and 10 adds/h; the PAT limit lives at `bridge-account-tokens.mjs:202`; copy its `WINDOW_MS` convention, no new constant if it matches.
7. **Q7 (`last_used_at`)?** Drop the column. The plane cannot observe use and a never-filled column invites a UI that lies.
