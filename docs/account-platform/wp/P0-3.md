# P0-3 — Shared key/value store and request guards for the bridge

Two new library modules. Nothing calls them yet: P0-4 wires them into `bridge-api.mjs`
(handoff, replay, sessions). Read the files named below yourself; this spec gives the contract,
not the code.

## Why
The bridge keeps single-use and throttling state in process `Map`s (`scripts/bridge-api.mjs:402-419`
replay store, `:1632-1660` handoff store, `scripts/bridge-ratelimit.mjs`). With two replicas a handoff
token minted on A cannot be consumed on B, or can be consumed once on each. The auth gateway already
solved this: `apps/opposite-osiris/scripts/auth/store.mjs` in the root repo (`/home/dlesieur/Documents/groot`),
a bounded memory store plus a zero-dependency RESP Redis client. The bridge image cannot import across
apps, so you PORT it (say so in the header comment, with the source path).

## OWNS
New only: `scripts/bridge-kv.mjs`, `scripts/bridge-guard.mjs`, `tests/bridge/bridge-kv.test.mjs`,
`tests/bridge/bridge-guard.test.mjs`. Every file ≤300 lines. Node built-ins only, no new dependency.
Not yours: every other file, including `bridge-api.mjs`, `bridge-ratelimit.mjs` (its callers stay as
they are), both Dockerfiles, `.env*`.

## `bridge-kv.mjs`
`createKv({ redisUrl = '', required = false, commandTimeoutMs = 1000, memory = {}, logger = console })` returns:

| Method | Meaning |
|---|---|
| `backend()` | `'redis'` or `'memory'` |
| `get(key)` / `del(key)` | string or `null` / void |
| `set(key, value, ttlMs)` | `ttlMs` required, positive integer |
| `setNx(key, value, ttlMs)` | `true` only for the caller that created the key (`SET … PX … NX`) |
| `getDel(key)` | the value once, then `null` for everyone (`GETDEL`; the compose Redis is 7) |
| `incrWithTtl(key, ttlMs)` | the new count; the TTL is set when the count is 1 |
| `close()` | ends the socket and the sweeper |

- Every key is prefixed `osb:` inside the module. Values are strings; JSON is the caller's job.
- `required: false`: Redis when connected, the bounded memory store otherwise (store.mjs behaviour).
- `required: true` (P0-4 sets it on a multi-replica deploy): when Redis is not connected, or a command
  fails or exceeds `commandTimeoutMs`, every method rejects with an `Error` carrying `{ status: 503,
  code: 'kv_unavailable' }` and a fixed message (the `pgError` shape of `bridge-pg.mjs`; every error
  this spec names has that shape). Never a memory fallback:
  a memory fallback on two replicas is exactly the double-consume this module exists to stop.
- Every Redis command has a timeout in both modes; a hung Redis must not hang a request.
- Invalid arguments (empty key, non-string value, bad ttl) throw `TypeError`.
- Caveat lines required for: the memory store's eviction (oldest first, so a flood evicts live
  tokens), and non-required mode (a Redis flap between `set` and `getDel` loses the key).

## `bridge-guard.mjs`
- `clientMeta(request, { ipHeader, hashSecret })` → `{ ipPrefix, ipHash, userAgent }`. The address is
  the header named by `ipHeader` (P0-4 passes `fly-client-ip` on fly) or else `request.socket.remoteAddress`
  — never the left-most `X-Forwarded-For` entry (anyone can write it; `bridge-public.mjs:27` does).
  `ipPrefix`: IPv4 `/24`, IPv6 `/48`, `::ffff:a.b.c.d` treated as IPv4, text form `a.b.c.0/24` /
  `2001:db8:1::/48` (the `cidr` column of `osionos_sessions`, P0-1). `ipHash`: hex HMAC-SHA256 keyed
  by `hashSecret`; with no secret it is `null`, never an unkeyed hash (all of IPv4 hashes in
  seconds). `userAgent`: at most 256 characters. Unparseable address → both IP fields `null`. The raw
  address is never returned or logged.
- `rateLimit(kv, key, { limit, windowMs })` — fixed window over `incrWithTtl`; above `limit` throws
  429 `rate_limited` with `retryAfterSeconds`. Caveat: a fixed window lets `2 × limit` through
  across a boundary.
- `grantSudo(kv, session, ttlMs = 600_000)` / `requireSudo(kv, session)` — the grant is keyed by the
  session id (`session.raw.jti`, only when it is a UUID; same rule as `asUser` in `bridge-pg.mjs`),
  never the user id, so sudo on one device does not unlock another. No UUID jti → `requireSudo`
  always throws 403 `sudo_required`.
- `writeAudit(pg, { session, meta, eventType, details = {} })` — inserts one row into
  `osionos_bridge_audit_events` through `pg.asService().post(...)` with `Prefer: return=minimal`.
  Columns: `provider 'osionos'`, `subject` and `actor_id` = the user id, `session_id` (UUID jti or
  null), `ip_hash`, `user_agent`, `event_type`, `details`. Table: `models/osionos-bridge-migration.sql:128`
  plus the columns P0-1 adds (`docs/account-platform/wp/P0-1.md` §4). Any failure rejects 503
  `audit_unavailable`: callers write the audit row BEFORE the irreversible action, so no audit means no
  action. `details` over 2048 serialized bytes → `TypeError`. JSDoc: details never carry a token,
  secret, password or code.
- `pg` is injected (the `createPg` shape of `bridge-pg.mjs`, which may not be merged in your tree):
  tests pass a fake with `asService()`.

## Tests (write first; `node:test`, the existing `tests/bridge/` style)
- kv, memory: TTL expiry, `setNx` once, `getDel` once, `incrWithTtl` counts and expires, eviction bound.
- kv, Redis: a fake RESP server on `node:net` inside the test (only the commands you send). Two
  `createKv` instances on one fake server stand for two replicas: `setNx` true on A then false on B;
  `getDel` returns the value on B and `null` on A. Server closed + `required: true` → every method 503;
  `required: false` → memory. A server that never answers → rejects within `commandTimeoutMs` + 200 ms.
- guard: `clientMeta` for IPv4, IPv6, mapped IPv4, garbage, a spoofed `X-Forwarded-For` ignored, no
  secret → `ipHash` null, a 300-character user agent; `rateLimit` allows `limit` then 429; sudo is per
  session (grant on jti A, require on jti B → 403); `writeAudit` sends exactly the columns above, and a
  failing fake pg → 503 `audit_unavailable`.
