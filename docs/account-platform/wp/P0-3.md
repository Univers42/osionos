## Why
The bridge keeps single-use and throttling state in process `Map`s (`scripts/bridge-api.mjs:402-419`
replay store, `:1632-1660` handoff store, `scripts/bridge-ratelimit.mjs`). With two replicas a handoff
token minted on A cannot be consumed on B, or can be consumed once on each. The auth gateway already
solved this: `apps/opposite-osiris/scripts/auth/store.mjs` in the root repo (`/home/dlesieur/Documents/groot`),
a bounded memory store plus a zero-dependency RESP Redis client. The bridge image cannot import across
apps, so you PORT it (say so in the header comment, with the source path).

## `bridge-kv.mjs`
`createKv({ redisUrl = '', required = false, commandTimeoutMs = 1000, memory = {}, logger = console })` returns:

| Method | Meaning |
|---|---|
| `backend()` | `'redis'` or `'memory'` |
| `get(key)` / `del(key)` | string or `null` / void |
| `set(key, value, ttlMs)` | `ttlMs` required, positive integer |
| `setNx(key, value, ttlMs)` | `true` only for the caller that created the key (`SET … PX … NX`) |
| `getDel(key)` | the value once, then `null` for everyone (`GETDEL`; the compose Redis is 7) |
| `incrWithTtl(key, ttlMs)` | the new count; sends `INCR` then `PEXPIRE k ttl NX` on EVERY call (store.mjs:264-265 sets the TTL only once, so a timeout between the two leaves a key that never expires — a permanent 429) |
| `ready()` | resolves when Redis is connected (tests await it; never a sleep) |
| `close()` | ends the socket, the sweeper and every timer |

- Every key is prefixed `osb:` inside the module. Values are strings; JSON is the caller's job.
  TTLs are milliseconds on the wire too (`PX`, `PEXPIRE`); store.mjs:256 sends `EX` seconds — do not copy it.
- `required: false`: Redis when connected, the bounded memory store otherwise (store.mjs behaviour).
- `required: true` (P0-4 sets it on a multi-replica deploy): when Redis is not connected, or a command
  fails or exceeds `commandTimeoutMs`, every method rejects with an `Error` carrying `{ status: 503,
  code: 'kv_unavailable' }` and a fixed message (the `pgError` shape of `bridge-pg.mjs`; every error
  this spec names has that shape). Never a memory fallback:
  a memory fallback on two replicas is exactly the double-consume this module exists to stop.
- Every Redis command has a timeout in both modes; a hung Redis must not hang a request. store.mjs
  matches replies to waiters in order (:224-227) and has no per-command timer (:235-244): dropping one
  waiter on timeout hands its late reply to the next caller. So on a timeout, or an AUTH/SELECT failure,
  DESTROY the socket — its close handler fails every queued waiter and schedules the reconnect
  (store.mjs:202-204 today leaves such a socket open and never reconnects). Clear and `unref` every timer.
- Misconfiguration fails loudly: `required: true` with an empty or unparseable `redisUrl` throws at
  `createKv` (store.mjs:186-188 only logs and stays on memory). In non-required mode, warn once per
  switch between Redis and memory. Never log the URL — it carries the password.
- Memory store: nothing may `await` between the check and the write in `setNx`/`getDel`. Counters and
  single-use keys live in two separate bounded maps, so a counter flood cannot evict a replay marker.
- Production Redis is an unpinned `apk add redis` on `alpine:3.21` (grobase
  `infra/docker/services/redis/Dockerfile:9,11`); `GETDEL` needs 6.2, `PEXPIRE … NX` needs 7.0. Say so in
  the header; P0-4 verifies the version before wiring.
- Invalid arguments (empty key, non-string value, bad ttl) throw `TypeError`.
- Caveat lines required for: the memory store's eviction (oldest first within each map; a flood of
  single-use keys evicts live replay markers, and a replay then SUCCEEDS), and non-required mode (a Redis
  flap between `set` and `getDel` loses the key, or consumes it twice across the switch).

## `bridge-guard.mjs`
- `clientMeta(request, { ipHeader, hashSecret })` → `{ ipPrefix, ipHash, userAgent }`. When `ipHeader`
  is set (lower-cased), the address is that header's value, which must be exactly ONE address passing
  `net.isIP` (a merged duplicate `a, b` → null); header missing → null, with NO socket fallback (in both
  deployments the socket peer is a proxy: nginx.conf:44 sets `X-Real-IP`, production comes through
  Vercel, `vercel.json:8`, so a fallback puts every user in one /24). When `ipHeader` is unset, the
  address is `request.socket.remoteAddress`. Never the left-most `X-Forwarded-For` entry (anyone can
  write it; `bridge-public.mjs:27` does).
  `ipPrefix`: IPv4 `/24`, IPv6 `/48`, `::ffff:a.b.c.d` treated as IPv4, text form `a.b.c.0/24` /
  `2001:db8:1::/48` (the `cidr` column of `osionos_sessions`, P0-1). Strip any `%zone`, expand `::`,
  zero the host bits (the P0-1 `cidr` cast refuses set host bits), canonicalise with
  `new URL('http://[…]').hostname`. Vectors: `2001:db8::1` → `2001:db8::/48`, `::1` → `::/48`,
  `::ffff:10.1.2.3` → `10.1.2.0/24`. `ipHash`: hex HMAC-SHA256 keyed by `hashSecret` over
  `'osb:ip:' + <normalised address>`; a blank or missing secret → `null`, never an unkeyed hash (all of
  IPv4 hashes in seconds). `userAgent`: `null` when absent; control characters stripped (a NUL fails
  the insert, so the audit fails and the action is blocked); truncated to 256 code points with
  `Array.from` (no lone surrogate). Unparseable address → both IP fields `null`. The raw address is
  never returned or logged.
- `rateLimit(kv, parts, { limit, windowMs })` — fixed window over `incrWithTtl`. `parts` is a non-empty
  array of non-empty strings (null, undefined, a number or '' → `TypeError`); the key is
  `rl:` + `parts.map(encodeURIComponent).join(':')`, so `['a:b']` and `['a','b']` are different buckets and
  an IPv6 part (`2001:db8::/48`) is fine. (The first version split a string key on ':' and rejected
  empty segments, which broke every IPv6 key — review of 84d4251b.) Above `limit` throws 429
  `rate_limited` with `retryAfterSeconds = ceil(windowMs / 1000)` (the field name of `bridge-api.mjs:2315`).
  Caveat: a fixed window lets `2 × limit` through across a boundary, and `retryAfterSeconds` is the
  window, not the time left. A kv 503 passes through unchanged — never turned into allow or 403.
- `grantSudo(kv, session, ttlMs = 600_000)` / `requireSudo(kv, session)` — the grant is stored under
  `sudo:<jti>` (`session.raw.jti`, only when it is a UUID; same rule as `asUser` in `bridge-pg.mjs`) with
  the user id as its value, never keyed by user id, so sudo on one device does not unlock another.
  `requireSudo` passes only when the stored value equals `session.userId`. No UUID jti → `grantSudo`
  throws 403 `sudo_required` and writes nothing (else every legacy session shares `sudo:undefined`),
  and `requireSudo` always throws 403 `sudo_required`. The `rl:` / `sudo:` prefixes keep the key spaces
  apart: `rateLimit(kv, 'sudo:…')` must not be able to create a grant.
- `writeAudit(pg, { session, meta, eventType, details = {} })` — inserts one row into
  `osionos_bridge_audit_events` through `pg.asService().post(path, row, { prefer: 'return=minimal' })`
  (bridge-pg reads only `opts.prefer`; a `headers` object is silently ignored). Call `pg.asService()`
  INSIDE the try: it throws synchronously when unconfigured. A `session.userId` that is not a UUID →
  `TypeError` (`subject UUID NOT NULL`, migration :131).
  Columns: `provider 'osionos'`, `subject` and `actor_id` = the user id, `session_id` (UUID jti or
  null), `ip_hash`, `user_agent`, `event_type`, `details`. Table: `models/osionos-bridge-migration.sql:128`
  plus the columns P0-1 adds (`docs/account-platform/wp/P0-1.md` §4). Any failure rejects 503
  `audit_unavailable`: callers write the audit row BEFORE the irreversible action, so no audit means no
  action. JSDoc: a row records an ATTEMPT — the action can still fail after it. `details` must be a
  plain object, at most 2048 bytes by `Buffer.byteLength(JSON.stringify(details))`, else `TypeError`.
  JSDoc: details never carry a token, secret, password or code.
- `pg` is injected (the `createPg` shape of `bridge-pg.mjs`, which may not be merged in your tree):
  tests pass a fake with `asService()`.

## Tests (write first; `node:test`, the existing `tests/bridge/` style)
- kv, memory: TTL expiry, `setNx` once, `getDel` once, two concurrent `setNx` under `Promise.all` give
  exactly one `true`, `incrWithTtl` counts and expires, a counter flood does not evict a single-use key.
- kv, Redis: a fake RESP server on `node:net` inside the test (only the commands you send) that
  RECORDS every command: assert the exact `SET osb:k v PX <ms> NX`, `GETDEL osb:k`, `INCR` + `PEXPIRE … NX`.
  A server that delays its first reply past the timeout: the second command still gets its OWN reply.
  `required: true` with `redisUrl: ''` throws at `createKv`. Two
  `createKv` instances on one fake server (await `ready()`) stand for two replicas: `setNx` true on A then false on B;
  `getDel` returns the value on B and `null` on A. Server closed + `required: true` → every method 503;
  `required: false` → memory. A server that never answers → rejects within `commandTimeoutMs` + 200 ms.
- guard: `clientMeta` for the three vectors above, garbage, `a, b`, `fe80::1%eth0`, a spoofed
  `X-Forwarded-For` ignored, `ipHeader` set but missing → null, blank secret → `ipHash` null, a user agent
  with a NUL and a 300-code-point emoji string; `rateLimit` allows `limit` then 429, a `null` segment →
  TypeError, a kv 503 passes through; sudo is per session (grant on jti A, require on jti B → 403), a
  value for another user → 403, a non-UUID jti → `grantSudo` 403 and no key written,
  `rateLimit(kv, 'sudo:<jti>')` then `requireSudo` → 403; `writeAudit` sends exactly the columns above
  with `prefer`, `asService()` throwing → 503 `audit_unavailable`, a failing fake pg → 503, a non-UUID
  user → TypeError.
