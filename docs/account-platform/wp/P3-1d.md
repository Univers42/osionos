## What the real code changes about P3-1.md

   (`src/scripts/portal.ts:524-543`) → `authClient.recover` (`src/hooks/useAuth.ts:264`) → gateway
   `POST /api/auth/recover` (`scripts/auth-gateway.mjs:1062`, handler `:800`) →
   `accountMail.requestRecovery` (`scripts/auth/account-mail.mjs:90`, always 202 with the same body,
   `ACCOUNT_MAIL_ACCEPTED`, per-address bucket 3/h `:41-47`). Reset: `src/pages/auth/reset-password.astro`
   posts `/reset-password` (`:141`) → `linkFlows.resetPassword` (`scripts/auth/link-flows.mjs:129`;
   signed link, TOTP step-up, global logout, session cut-off). d1 therefore audits and closes gaps; it
   does not rebuild this flow.
2. **The email "OTP" in the gateway is not a sign-in.** `scripts/auth/login-otp.mjs` is a second factor
   after a correct password (`/api/auth/mfa/email/*`, routes `auth-gateway.mjs:1069`, cookie ticket
   `login-otp.mjs` `TICKET_COOKIE`). Passwordless OTP sign-in does not exist: `rg -n "signInWithOtp|/otp"
   src scripts` finds nothing, and `vendor/grobase-js/lib/domains/auth.d.ts` has no OTP method.
3. **Turnstile is real only when a site key is built in.** `readTurnstileToken`
   (`portal.ts:70-79`) and `mountTurnstile` (`:81-90`) return `localhost-turnstile-token` whenever
   `PUBLIC_TURNSTILE_SITE_KEY` is empty or `local-dev-turnstile-key`; `auth-config.ts:19-24` also blanks
   Cloudflare's test keys. Gateway side, `verifyTurnstile` (`auth-gateway.mjs:214-222`) accepts that token
   only with `TURNSTILE_BYPASS_LOCAL=true`, and `collectStartupViolations`
   (`scripts/auth/guards.mjs:82-112`) refuses to boot on a public https origin with the bypass, no secret
   or a dummy secret. `deploy/fly/fly.toml:31` sets the bypass false. So the production gap is the
   **client build**: nothing fails the build when the site key is missing, and the bypass literal is
   shipped in the bundle.
4. **The website never calls the bridge's `POST /api/auth/exchange`.** Its handoff is the gateway
   `POST /api/auth/osionos-session` (`auth-gateway.mjs:1068`, handler `:950-1012`), which verifies a GoTrue
   bearer through `createClient(...).auth.getUser()` (`:964`), signs `{provider, subject, email,
   emailVerified, jti}` and posts it to `OSIONOS_BRIDGE_URL` (`:991`, bridge `/api/auth/bridge/session`),
   then returns `redirectUrl`, which `portal.ts:706-729` follows after `isTrustedOsionosRedirect`
   (`:138`). The bridge exchange (`/home/dlesieur/Documents/groot-wt/integration/app/scripts/bridge-auth-exchange.mjs`)
   cannot serve that page: CORS allows one origin, `config.allowedOrigin` = the osionos app
   (`bridge-api.mjs:188`, `:2294`), and it answers session JSON, not a redirect. See Open question 1.
5. **OAuth is configured in grobase already, disabled by default** (d2 context): credentials plus wiring.

## Contract

1. **Real Turnstile in production.** The site build fails (`astro build`) when `PUBLIC_SITE_URL` is a
   public https origin and `PUBLIC_TURNSTILE_SITE_KEY` is empty, `local-dev-turnstile-key` or a
   Cloudflare test key. `readTurnstileToken`/`mountTurnstile` return the bypass literal only when
   `import.meta.env.DEV` or the site origin is loopback; otherwise they return `''` and the form shows
   "Please complete the verification check" (`portal.ts:569-574`). Register, login, recover, resend and the
   new OTP request all send the widget token; the widget resets after each submit (a Turnstile token is
   single-use).
2. **Forgot/reset.** Keep the flow; add Turnstile per item 1 and the equality test. No UI rewrite.
3. **Email OTP sign-in, two gateway routes** (the gateway, not the browser, requests the code, so
   Turnstile and the enumeration rule apply):
   - `POST /api/auth/otp/request` `{email, turnstileToken}` via `protectedAction`
     (`auth-gateway.mjs:557`) with a new `RATE_LIMITS.otpRequest`. Always 202 `ACCOUNT_MAIL_ACCEPTED`.
     Job: normalized email valid, deliverable domain, `profiles.emailExists` true, account not banned,
     then admin `generate_link {type:'magiclink', email}`, mail only the numeric `email_otp` from the
     answer (never `action_link`, never `hashed_token`). Per-address bucket reuses `accept`
     (`account-mail.mjs:41`), 3 per hour.
     **Never call `generate_link` for an address without a profile: GoTrue creates the user.**
   - Verify is a browser call to GoTrue `POST /auth/v1/verify {type:'magiclink'|'email', email, token}`
     through the existing `/auth/` rewrite; the response's `access_token` then goes to
     `authClient.osionosSession` (`useAuth.ts:288`), exactly like the password path. The 6-digit code is
     validated client side with the `^\d{6}$` shape used at `useAuth.ts` `verifyLoginCode`.
4. **Handoff.** The OTP access token is passed to `osionosSession` (gateway → bridge `/bridge/session` →
   `redirectUrl`). The gateway handler must additionally reject, for this path, a token whose `amr` is
   not `otp` newest (decode the payload after `getUser` succeeded, same rule as
   `authMethodFromClaims`). If open question 1 is answered "use the exchange", this item becomes the
   bridge-side CORS and redirect work and d1 is blocked on it.

## Security edge

- **Enumeration:** status, body and (as far as the queue allows) latency do not depend on existence; mail
  work runs after the response (`accept` → `queue.push`). Recovery conforms; the test pins it.
  `/availability` already tells a stranger whether an email is taken; out of scope, noted.
- **Takeover:** a code is bound to one email and capped by GoTrue's own attempt limits. The request
  route accepts no `redirect_to`. A password reset already logs out every GoTrue session
  (`link-flows.mjs` `finish`), so older sessions do not outlive it.
- **Rate limits:** per IP (`rateLimit`, `auth-gateway.mjs:167`), 3 per address per hour, the daily mail cap
  `scripts/auth/mail-daily-cap.mjs`. Caveat for the code: the address bucket counts requests, so an
  attacker can exhaust the owner's 3 codes (same trade-off as recovery).
- **Bypass:** the gateway already refuses to boot with it in production (`guards.mjs:90`); the client
  build guard stops a missing site key shipping silently.
- **Direct Kong `/auth/v1/otp`:** reachable from the public site, unrelated to the gateway's Turnstile.
  d1 cannot close it (root/Kong repo); it is Open question 4.

## Contract

1. Portal shows "Continue with Google / GitHub / 42" only for providers the deployment enables (a
   `PUBLIC_*` list read at build; a disabled provider renders no button). Click → `window.location` to
   `signInWithOAuth` URL with `redirect_to` set to the website callback page (allow-listed).
2. Callback page reads the GoTrue result from the URL **fragment** (never a query string, so it stays out
   of server logs), removes it with `history.replaceState` before any other work, then runs the
   collision guard and `authClient.osionosSession(accessToken)`, the same handoff as d1.
3. **Collision guard (server side, gateway route `POST /api/auth/oauth/check`, bearer = GoTrue token):**
   read the user with `getUser` and the admin user (identities). Allow only if (a) the user has exactly
   one identity, or (b) every identity is `email_verified` and the account's email was confirmed before
   this sign-in. Otherwise answer 409 `oauth_email_collision`, revoke that token's session (GoTrue
   logout) and do not call `osionosSession`. `osionosSession` already sends `emailVerified`
   (`auth-gateway.mjs:985`); the bridge must keep refusing unverified (P3-1 rule).

## Security edge

- **Takeover:** the classic attack is a provider that lets an attacker register `victim@example.com`
  without proving the inbox; a silent link gives them the victim's account. The guard above, plus a test
  with a fake GoTrue returning an identity with `email_verified:false` over a password account.
- **Token in the URL fragment:** replace history first; callback origin must be exactly the allow-listed
  URL; reject any `redirect_to` not on `GOTRUE_URI_ALLOW_LIST` (GoTrue does; the page re-checks
  `isTrustedOsionosRedirect`, `portal.ts:138`).
- **Enumeration:** the 409 text is the same for any colliding address and names no provider; per-IP limited.
- **Bridge exchange limit:** the exchange refuses tokens whose newest `amr` is not `oauth`/`otp`; a token
  refreshed after sign-in is refused (`bridge-auth-exchange.mjs:12-13`), so do not refresh before handoff.
