# P2-5 — Settings, honest and finished: real states, no invented data, every destructive action confirmed

**Repo/branch:** app = `/home/dlesieur/Documents/groot-wt/integration/app` on `feat/account-platform`. No root SQL, no bridge change.

## Decisions (D-P2-5, 2026-10-22) — binding

The plan's P2-5 was a design pass: the ui-ux-pro-max checklist, plus screenshots in light and dark at 375 and 1440. On 2026-10-22 the user asked for the existing settings to be **improved, not duplicated**: "some implementations ideas were good, just not enough user friendly, and not enough appealing, not enough functional". The inventory `target/specs/R-SETTINGS.md` (spot-checked 5/5 on 2026-10-22) shows why:
- Every panel renders before its data arrives.
- Nothing shows a failed load.
- Stores invent "connected" accounts and an "Education Plus" plan.
- Several destructive buttons act on one click.
- About a dozen controls do nothing.

So P2-5 becomes that pass, done on the code that exists:

1. **Library first.** P2-5-a adds the shared pieces once: one hydration hook, one panel status component, one empty state, a labelled and async-aware confirm, and shared e2e helpers. The panel parts only call them.
2. **Honesty over polish.** When a control does nothing, it is removed or marked unavailable in plain words; it is never kept as decoration. When data does not exist, the panel shows an empty state; it never shows a fake row.
3. **No new route, no new store, no new section.** A panel that needs a missing route says so, and it uses P1-5's honest outcome helpers (`runAccountAction` and `accountActionNotice`, `src/features/settings/model/settingsCalls.ts:51-88`).
4. **`profile/**`, `people/**`, `permissions/**` and `public-pages/**` are out of scope.** P1-6 rewrites `profile/`, the user's own fresh work lives in `people/`, `permissions/` is P5-1's, and P5-5 rewrites `public-pages/` in place.
5. **The visual language is the existing kit.** Use `Section`, `SettingRow`, `FeatureCard`, `Button` tones, `--osio-*` tokens and the control radius that `tests/e2e/functional/settingsKit.spec.mjs` already pins. Add no colour, font or shadow.
6. **Order:**
   - First, a and b in parallel, since their OWNS are disjoint.
   - Then c1 and c2 in parallel, both after a.
   - Last, d, after c1, c2 and P1-6.

## Existing (what the parts extend)

- **`runAsync` and `runMaybeAsync` swallow every rejection** (`src/features/settings/model/settingsCalls.ts:17-23`). Panels call `runAsync(hydrate(...))` and render the empty state at once, so no panel can show "loading" or "couldn't load" (R-SETTINGS §2 gaps 1 and 9).
- **The kit:**
  - `Section` derives its deep-link anchor from its title (`src/features/settings/ui/settingsKit.tsx:18-24`, `:26`), so renaming a heading breaks `?settings=<id>#<anchor>`.
  - `DataTable` has no empty state (`:50-69`). Panels push a fake row instead, for example `['No completed imports yet', 'Local', '', '']` (`src/features/settings/import/ImportPanel.tsx:97`).
- **`ConfirmModal` and `TypedConfirmModal`** (`src/features/settings/ui/ConfirmModals.tsx:17-37`) have no busy state. The typed input has only a placeholder, no label. A second confirm implementation exists: `DisconnectAllConfirm` (`src/features/settings/mcp/McpManageTab.tsx:56`).
- **Stores invent state:**
  - `defaultConnections` returns a *connected* osionos Mail and Calendar for every user (`src/store/settings/defaults.ts:105-112`).
  - `defaultBillingState` says "Education Plus" (`:144-158`).
- **The e2e settings helpers** (`openSettings`, `searchSettings`, `region`, `nav`) are copied into each spec (`tests/e2e/functional/settingsHonesty.spec.mjs:21-44`).

## Contract

### P2-5-a — the shared pieces (first; parallel with b)

1. **`useSettingsHydration(load, deps)`** in a new `src/features/settings/model/settingsHydration.ts`. No hydration primitive exists, and `runAsync` must stay fire-and-forget for writes.
   - It returns `{ status: 'loading' | 'ready' | 'error', error: string | null, retry: () => void }`.
   - A pure `nextHydrationState(state, event)` carries the logic, so a canvas test can pin it.
   - Ignore a load that settles after unmount, or after a newer load started (generation counter).
   - `retry` re-runs `load`.
2. **`PanelStatus`** in `settingsKit.tsx`: `{ status, error, onRetry, children }`.
   - `loading` renders three skeleton rows the height of a `SettingRow`, `aria-busy="true"`, with one visually-hidden "Loading…". The pulse uses the existing motion tokens and stops when the app's reduced-motion preference (P1-7) is on.
   - `error` renders an inline callout: `role="alert"`, danger-tinted with `--osio-danger*` tokens, the title "Couldn't load these settings", the message, and a **Retry** button.
   - `ready` renders `children`.
3. **`EmptyState`** in `settingsKit.tsx`: `{ icon?, title, hint?, action? }`. It reuses `FeatureCard`'s 32 px icon tile (`settingsKit.tsx:86-97`), centred, with one-line sentence-case copy.
   - `DataTable` gains `empty?: React.ReactNode`. When `rows` is empty it renders `empty` in a single full-width row.
4. **`Section`** gains an optional `anchor?: string`, which wins over `anchorFromTitle`. Callers without it behave exactly as today.
5. **`ConfirmModal` and `TypedConfirmModal`.** These changes are additive; existing callers compile unchanged.
   - `onConfirm` may return a Promise. While it is pending, both buttons are disabled and the action label reads "<actionLabel>…".
   - A rejection keeps the modal open and shows the message in a `role="alert"` line.
   - The message paragraph is the dialog's `aria-describedby` target.
   - The typed input gets a visible label "Type <confirmText> to confirm", bound with `htmlFor`/`id`.
6. **`SettingsSearch`** shows "No settings match “<query>”" in a `role="status"` line when there are no hits (R-SETTINGS §3).
7. **`tests/e2e/support/settingsHelpers.mjs`** exports `region`, `nav`, `openSettings`, `searchSettings` and `openSection(page, label)`. `settingsHonesty.spec.mjs` and `settingsKit.spec.mjs` import them, and their local copies are deleted, so behaviour does not change.
