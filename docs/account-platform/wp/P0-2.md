# P0-2 — `bridge-pg.mjs`: per-user PostgREST client + pagination primitives

## Why
The bridge reaches Postgres (PostgREST behind Kong) with the **service-role key only**
(`baasRest`, `scripts/bridge-api.mjs:513-534`), so a forgotten `user_id=eq.` filter leaks one
user's data to another. New account tables (profiles, settings, sessions…) will instead be read
with a **short-lived per-user JWT**; Postgres row-level security then enforces
`user_id = osionos_account_uid()` (that SQL ships in another package — you only build the client).
This package also adds the paging/chunking primitives the account routes will share:
`in.(…)` URLs currently break near 90 ids (Kong header buffer, see the comment just below
`idsFilter` at `scripts/bridge-api.mjs:1371-1375`), and list routes need keyset paging.

## Contract (exports of `scripts/bridge-pg.mjs`)

```js
export const ACCOUNT_JWT_AUDIENCE = 'osionos-account';
export const ACCOUNT_DB_ROLE = 'osionos_account_user';
export const ACCOUNT_JWT_TTL_SECONDS = 120;

mintAccountJwt({ userId, sessionId, secret, nowMs = Date.now(), ttlSeconds = 120 }) -> string
```
- Claims are EXACTLY `{ iss: 'supabase', aud, role, sub: userId, sid: sessionId, iat, exp }`;
  `sid` is omitted when `sessionId` is absent; `iat = floor(nowMs/1000)`, `exp = iat + ttlSeconds`.
- `secret` empty or whitespace → throw `{ status: 503, code: 'account_plane_unavailable' }`.
  Never fall back to the service key.
- `userId` not a UUID (`/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`) →
  throw `{ status: 400, code: 'invalid_subject' }`.

```js
createPg({ config, env = process.env, fetchImpl = fetch, timeoutMs = BAAS_FETCH_TIMEOUT_MS, now = Date.now })
  -> { asService(), asUser(session) }
```
- `config` has the shape built in `bridge-api.mjs:164-185`: `{ baasUrl, publicApiKey, serviceKey }`.
  The JWT secret is `env.JWT_SECRET`.
- Base URL: `env.OSIONOS_POSTGREST_URL` (trailing `/` trimmed) when set, else `${config.baasUrl}/rest/v1`.
- `asService()` headers: `apikey: serviceKey`, `Authorization: Bearer <serviceKey>`.
  Empty `serviceKey` → `{ status: 503, code: 'baas_unconfigured' }`.
- `asUser(session)`: `session` is the object `verifyAppSessionToken` returns
  (`bridge-api.mjs:486-492`): `{ userId, workspaceIds, roles, isAdmin, raw }`. There is no
  `session.jti`; the token id is `session.raw?.jti`. Pass `sessionId: session.raw?.jti` and put
  `sid` in the claims only when that value is a UUID (same regex as `userId`). Headers:
  `Authorization: Bearer <mintAccountJwt({ userId: session.userId, sessionId, … })>` and
  `apikey: publicApiKey` (Kong requires an apikey; omit the header when `publicApiKey` is empty).
  The service key must never appear in any header, URL or body of an `asUser` request.
- Both return a client `{ get(path), post(path, body, opts), patch(path, body, opts), del(path, opts), rpc(fn, args) }`;
  `opts.prefer` sets `Prefer`; `rpc(fn, args)` = `post('rpc/' + fn, args)`; `fn` must match
  `/^[a-z_][a-z0-9_]*$/`. `Accept: application/json`; `Content-Type: application/json` when there is a body.
- Path guard, two layers, both required:
  1. Reject (`TypeError`) a `path` that starts with `/`, or contains `..`, `://`, `\\`, `%2e`
     in any letter case (`%2E`, `%2e`), `%2f`/`%5c` in any case, or a control character (`\x00-\x1f`, `\x7f`).
  2. After building `const url = new URL(`${base}/${path}`)`, require
     `url.origin === new URL(base).origin` and `url.pathname.startsWith(new URL(base).pathname + '/')`;
     otherwise `TypeError`. Why: `new URL(base + '/%2E%2e/%2e%2e/auth/v1/admin/users').pathname`
     is `/auth/v1/admin/users` (verified on Node 22) — GoTrue's admin API reached with the service key.
- Each request is bounded by `AbortSignal.timeout(timeoutMs)`.
- The `try/catch` that produces `baas_unreachable` wraps ONLY the `fetchImpl(...)` call. Errors
  from `mintAccountJwt` (503/400), the path guard (`TypeError`) and `rpc` name check propagate
  unchanged — never re-labelled as `baas_unreachable`.
- Status mapping on a non-2xx answer. The error carries `status`, `code`, `upstreamStatus`,
  `upstreamText` (first 160 chars of the body) and `upstreamCode` (the JSON body's `code` field,
  e.g. `42501` for an RLS refusal, `PGRST205` for a missing table; `undefined` when absent or not JSON).
  The error `message` is a FIXED string per code (e.g. `'Account data request failed.'`) and must
  NEVER contain `upstreamText`: route handlers return `message` to the browser
  (`bridge-realtime-token.mjs:96`) and a PostgREST 409 detail can quote another row's values.

| upstream | asService | asUser |
|---|---|---|
| 400 | 422 `invalid_request` | 422 `invalid_request` |
| 401 / 403 | 403 `forbidden` | 503 `account_plane_unavailable` (the role/JWT setup is wrong — never surface as the user's fault) |
| 404 | 404 `not_found` | 503 `account_plane_unavailable` (through PostgREST a missing row is `200 []`; a 404 is a missing table/function or a Kong route miss) |
| 409 | 409 `conflict` | 409 `conflict` |
| 429 | 429 `rate_limited` | 429 `rate_limited` |
| other | 502 `baas_failed` | 502 `baas_failed` |

- Network error or timeout → 503 `baas_unreachable`. A 2xx body goes through `readBaasJson(response, { service, empty: null, fail })`,
  where `fail(message)` returns an Error with `{ status: 502, code: 'baas_failed' }`.

```js
idChunks(ids, size = 50) -> string[][]
inFilter(column, ids) -> string
```
- `idChunks`: drop `null`/`undefined`/`''`, de-duplicate keeping first-seen order, split in
  chunks of `size`; `size` must be an integer 1..500 else `RangeError`. `[]` → `[]`.
  Add a `Caveat:` above it: the 50 default was measured with unquoted ids (`bridge-api.mjs:1371-1379`);
  `inFilter` quoting adds 6 B per id, so 50 UUIDs are ~2.15 KB instead of ~1.85 KB, leaving
  ~1.5 KB of Kong's 4 KB header buffer for the rest of the query string.
- `inFilter`: `column` must match `/^[a-z_][a-z0-9_]*$/` else `TypeError`. Each value is wrapped
  in double quotes with `\` → `\\` and `"` → `\"`, then `encodeURIComponent`-encoded; result
  `${column}=in.(v1,v2,…)`. Empty `ids` → `TypeError` (an empty `in.()` is a PostgREST error).

```js
encodeCursor(values) -> string            // base64url(JSON.stringify(values))
decodeCursor(token, arity) -> values
keyset({ order, cursor, limit, maxLimit = 100 }) -> { query, take }
pageOf(rows, order, take) -> { items, nextCursor }
```
- `decodeCursor` throws `{ status: 422, code: 'invalid_cursor' }` for: length > 512, not
  base64url, not JSON, not an array, length ≠ `arity`, an element that is not a string or finite number.
- `keyset`: `order` = 1..3 entries `[column, 'asc'|'desc']` (column regex as above; the last
  entry is the unique tie-breaker; every order column must be NOT NULL in the table — say so in
  the JSDoc). `limit`: `n = Number(limit)`; absent or non-finite → 20; then `Math.trunc` and clamp
  to `1..maxLimit` (`0` → 1, `'50'` → 50, `'abc'` → 20, `1000` → `maxLimit`). `take` = that value.
  Each column uses its OWN direction's operator (mixed `[a,'desc'],[b,'asc']` → `a.lt` … `b.gt`). `query` = `order=a.desc,b.desc&limit=<take+1>` and, when `cursor`
  is given, an `or=(…)` keyset filter — for order `(a desc, b desc)` and cursor `[x, y]`:
  `or=(a.lt."x",and(a.eq."x",b.lt."y"))` (values quoted + encoded as in `inFilter`; `asc` uses
  `gt`; generalise to 3 columns). Fetching `take+1` rows tells whether a next page exists.
- `pageOf`: `items = rows.slice(0, take)`; `nextCursor` = cursor of `rows[take-1]`'s order
  columns when `rows.length > take`, else `null`. A `null`/`undefined` order-column value in that
  row → throw `TypeError` (a null in the cursor would make page 2 fail with 422 forever).
- Add `Caveat:` comments: (a) the cursor is not signed — tampering only moves the page start; it
  can never widen the rows a caller may see, because every filter is still applied server-side;
  (b) numbers go through JSON, so a `bigint` column above 2^53 loses precision — page by a uuid
  or timestamptz tie-breaker, never a raw bigint id.

## Tests (`tests/bridge/bridge-pg.test.mjs`, write first)
Use a fake `fetchImpl` that records `(url, init)` and returns `new Response(...)`.
1. `mintAccountJwt`: decode header+payload, recompute the HS256 signature with the secret and
   assert it matches; assert the exact claim key set; `exp - iat === 120`; `sid` absent without jti.
2. Blank secret → 503 `account_plane_unavailable`; non-UUID subject → 400 `invalid_subject`.
3. `asUser` request built from a REAL `verifyAppSessionToken` result: sign a token with
   `signAppSessionToken` (`bridge-api.mjs:423`) — or, if importing `bridge-api.mjs` starts a
   server, construct the exact object shape of `:486-492` with `raw.jti` set. Authorization is a
   JWT for that user with `sid === raw.jti`; a non-UUID `raw.jti` → no `sid` claim; `apikey` =
   public key; the service key string appears nowhere in url/headers/body (scan all of them).
4. `asService` uses the service key; empty service key → 503 `baas_unconfigured`.
5. `OSIONOS_POSTGREST_URL` overrides the base; trailing slash trimmed.
6. Every row of the status-mapping table, for both clients; network error and timeout → 503.
   `upstreamCode` is read from a JSON error body; the error `message` never contains the body text
   (use a body with a recognisable marker string and assert it is absent from `message`).
7. Path guard: `/x`, `a/../b`, `http://x`, `a\nb`, `a\\b`, `%2E%2e/%2e%2e/auth/v1/admin/users`,
   `x/%2F..`, `%5c` all throw `TypeError` and `fetchImpl` is never called; `rpc` name guard.
   Error scope: a blank secret on `asUser` rejects with 503 `account_plane_unavailable` (not
   `baas_unreachable`), and a bad path rejects with `TypeError`, with `fetchImpl` never called.
8. `idChunks`: 0, 1, 50, 51, 500 ids; duplicates/empties removed; size 0 / 501 / 1.5 → RangeError.
9. `inFilter`: a value with `,` `.` `(` `)` `"` `\` round-trips correctly encoded; bad column throws.
10. Cursor: round-trip; every malformed case → 422; `keyset` output for 1, 2 and 3 columns, asc,
    desc and mixed, with and without cursor; limit parsing (0, absent, `'50'`, `'abc'`, 1000).
    Hostile cursor values (`"`, `)`, `,`, `&`, `+`, and `'2026-10-22T00:00:00+00:00'`) stay inside
    ONE `or=` parameter: `new URLSearchParams(query).getAll('or').length === 1` and no stray `&`.
11. `pageOf`: exactly `take` rows → `nextCursor: null`; `take+1` rows → cursor of row `take-1`;
    a null order value in row `take-1` → `TypeError`.
