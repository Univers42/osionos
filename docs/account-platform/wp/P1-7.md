# P1-7 — accessibility preferences that change the app, not just a toggle

Repo: osionos app, branch `feat/acct-P1-7` from `feat/account-platform` (after P1-3b, which is
merged). Frontend only. Facts are from research run R-P1-7 (2026-10-22); re-check each anchor
before editing.

## Why
- None of the accessibility preferences the platform promises exists: link underlines,
  hovercards, animated images, motion override, URL paste. `UserPreferences`
  (`src/store/settings/types.ts:70-86`) has no such keys, and nothing reads one.
- What the app does today, hard-wired:
  - **Motion** follows only the OS: the global reset in `src/app/styles/global.css:895-908`, and
    `<MotionConfig reducedMotion="user">` at `src/app/main.tsx:58`.
  - **Video covers** play even under reduced motion, deliberately
    (`src/entities/page/ui/CoverMediaElement.tsx:62-67`: on this stack the OS query is often just
    GTK "animations off").
  - **A pasted bare URL** always becomes `[hostname](url)`
    (`src/features/block-editor/model/usePlaygroundBlockEditor.ts:1621-1632`).
- So a user who needs reduced motion on a desktop whose OS does not say so, or who wants covers
  still, or plain URLs, has no way to get it.

## Decisions
- **D1 — Home: the existing Appearance seam** (`src/shared/config/theme.ts`: `Appearance`,
  `parseAppearance`, `applyAppearance`, `persistAppearance`, `APPEARANCE_ATTRIBUTES`; the
  pre-paint mirror in `index.html:32-49`).
  - Three of the five preferences must hold before first paint (motion, underlines, covers), and
    this seam is the one place that already does that, with tests (`tests/canvas/tokens-accents.test.ts`,
    `tests/e2e/functional/appearancePrefs.spec.mjs`).
  - It is device-local, like theme and density today; account sync of the whole Appearance object
    is a later, separate change.
  - All five live there, so one panel reads one object.
- **D2 — Every default is today's behaviour.** No user sees a change until they choose one. The
  attribute is absent at the default, as `applyAppearance` already does for density
  (`theme.ts:211`).
- **D3 — Not in this package:**
  - **Character-key shortcuts.** The dispatcher handles only modifier chords
    (`src/features/automations/model/useAutomationDispatcher.ts:92-94`). First search `src/`
    (excluding `notion-database-sys`) for keydown handlers that act on a bare printable key
    outside a text field. If you find none, do not add the preference and report the search
    (command and output). If you find some, list them and stop; it becomes its own package. A
    toggle that controls nothing is not shipped.
  - **Screen-reader hints.** This needs a design first (which events, what text). It is recorded
    in the ledger, not built.

## Contracts
`Appearance` gains five fields. `parseAppearance` validates each with `oneOf` like the existing
axes, and a bad value falls back to the default per field.

| Field | Values (default first) | `<html>` attribute when not default | Effect |
|---|---|---|---|
| `linkUnderline` | `'default' \| 'always'` | `data-link-underline="always"` | every `a[href]` and inline editor link is underlined at rest (find today's rule and say what "default" is) |
| `motion` | `'system' \| 'reduce' \| 'full'` | `data-motion="reduce\|full"` | see 1 |
| `animatedImages` | `'play' \| 'system' \| 'still'` | `data-animated-images="system\|still"` | see 2 |
| `hovercards` | `'on' \| 'off'` | `data-hovercards="off"` | see 3 |
| `urlPaste` | `'link' \| 'plain'` | none (behaviour only) | see 4 |

1. **Motion.**
   - **CSS:** the global reset applies when `(prefers-reduced-motion: reduce)` and the root is not
     `[data-motion="full"]`, OR when the root is `[data-motion="reduce"]`, whatever the OS says. One
     rule set, no duplicated declarations: use `:root:not([data-motion="full"])` inside the media
     query and a `:root[data-motion="reduce"]` copy of the selector list outside it.
   - **JS:** `MotionConfig.reducedMotion` maps `system → "user"`, `reduce → "always"`,
     `full → "never"`, and follows changes without a reload (a small component reading the
     Appearance; say how it learns of a change).
   - **App readers of the media query** move to one exported `prefersReducedMotion()` that honours
     the attribute. That covers `coverMedia.ts:32` (already exported; extend it),
     `PageOutlineRail.tsx:98` and `useMonacoEditor.ts:128`.
   - **Not covered:** the vendored readers (`notion-database-sys/.../useViewTabReorder.ts:28`,
     `ViewSlideStage.tsx:56`) and `packages/legacy-graph-engine` (its core may not import `@/*`).
     They keep following the OS only. State that in a `Caveat:` on `prefersReducedMotion`.
2. **Animated images.**
   - **Video covers:**
     - `play` keeps today's behaviour;
     - `still` never autoplays: show the first frame (`preload="metadata"`, no `play()`) and give
       the cover an accessible play/pause button;
     - `system` behaves like `still` when `prefersReducedMotion()` is true, else `play`.
   - **GIF image blocks** (find the editor's image block renderer and say which file), under
     `still` (or `system` with reduced motion): render the image's first frame on a `<canvas>`
     (`drawImage` of a decoded `HTMLImageElement` paints the default frame), with the same
     alt text, size and a play button that swaps in the live `<img>`.
   - **Scope and Caveat:** only `.gif` URLs and `data:image/gif`. The `Caveat:` must say animated
     WebP/APNG are not detected and still animate, and that chat attachments and avatars are not
     covered (ledger follow-up).
3. **Hovercards.**
   - List every component that opens a person or page card on pointer hover (start with
     `src/features/settings/people/PeoplePeek.tsx`, `src/widgets/legacy-graph-explorer/LegacyNodeHoverPreview.tsx`,
     and any hover that renders `PageBlocksRenderer`), with file:line.
   - Under `off`, each opens on click or keyboard focus+Enter instead of on hover. Hover still
     shows the native `title` if one exists.
   - All of them go through one hook, `useHovercardsEnabled()`, next to the Appearance seam.
   - `SidebarEdgePeek` is a sidebar reveal, not a hovercard: leave it.
4. **URL paste.** Under `plain`, the bare-URL branch at `usePlaygroundBlockEditor.ts:1621` inserts
   the URL text unchanged. Nothing else in the paste handler changes. The existing `pastePlain`
   command still works under both values.
5. **Pre-paint.** `index.html`'s boot script applies `data-link-underline`, `data-motion`,
   `data-animated-images` and `data-hovercards` from the same `osionos:appearance` JSON, with the
   same allowlist style as the existing axes (`index.html:42-43`). Keep its comment true.
6. **UI.**
   - A new **Accessibility** block in `src/features/settings/preferences/PreferencesPanel.tsx`
     (128 lines; if it would pass 200, put the block in a sibling `AccessibilitySettings.tsx`),
     built from the settings kit the other blocks use. Each control has a visible label and a
     one-line description saying what it changes.
   - Append one anchor to the `preferences` section in `src/features/settings/model/sections.ts`:
     `{ id: "accessibility", label: "Accessibility", keywords: ["motion", "animation", "underline",
     "links", "hovercard", "gif", "paste", "url"] }`. Nothing else in the registry changes.

## Tests (write first, see them fail)
1. `tests/canvas/appearance-accessibility.test.ts`: `parseAppearance` round-trips each new field,
   falls back per field on a bad value, keeps the existing axes unchanged on an old stored object
   (no new keys), and `applyAppearance` sets or removes exactly the attributes in the table.
2. `tests/e2e/functional/accessibilityPrefs.spec.mjs`, in `appearancePrefs.spec.mjs`'s style
   (seed `osionos:appearance` with `addInitScript`, then assert):
   - `linkUnderline: always` → an editor link's computed `text-decoration-line` is `underline`;
     default → today's value;
   - `motion: reduce` with the OS not reducing → a known transition's computed duration ≤ 0.01ms;
     `motion: full` with `page.emulateMedia({ reducedMotion: 'reduce' })` → not collapsed; `system`
     follows the emulated media;
   - `animatedImages: still` → a video cover's `paused` is true and its play button plays it;
     `play` → it plays (today's case);
   - a GIF image block under `still` renders a canvas, not an animating `<img>`, until Play;
   - `hovercards: off` → hovering a person opens no card, and focus+Enter opens it;
   - `urlPaste: plain` → pasting `https://example.com/a` leaves exactly that text in the block;
     `link` → today's `[example.com](…)` link;
   - pre-paint: with `motion: reduce` seeded, `document.documentElement.dataset.motion` is
     `reduce` at `DOMContentLoaded` (read in an init script, before the app's module runs);
   - the Settings → Preferences → Accessibility controls change each attribute live, and the
     choice survives a reload.
