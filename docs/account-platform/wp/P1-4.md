# P1-4 — Settings from the `>` palette, `mod+,`, and a deep link

Depends on P1-3b: the section registry (`src/features/settings/model/sections.ts`) and
`openSettings(section?, anchor?)` (`model/settingsNav.ts`) exist in your tree. Read them first; they
are the only list of sections and the only way to open the tab. Do not add a second list.

## Goal
Every settings section and every anchor is one `>` command away, `mod+,` opens Settings, and
`?settings=<section>#<anchor>` opens the tab at that anchor.

## Contracts
- `settingsCommands.ts`: `settingsPaletteCommands(): PaletteCommand[]` built from the registry — one
  command per section (`Settings: <title>`) and one per anchor (`Settings: <section title> › <anchor label>`),
  group `Settings`, ids `settings.<section>` / `settings.<section>.<anchor>`, `keywords` = the anchor's
  keywords (plus the section label for a section), `run` → `openSettings(section, anchor?)`.
- `PaletteCommand` gains optional `keywords?: string[]` (additive). The `>` matcher also matches a
  query against keywords, ranked below a label match; existing results and their order for queries
  that match no keyword stay the same. `buildCommands` appends the settings commands; its de-dupe
  stays by label.
- Automations: command `openSettings` (title `Settings`, category `App`) with the default chord
  `mod+,`. It must not take a chord the defaults already bind (the dispatcher's own tests or a
  canvas assertion prove it).
- `settingsDeepLink.ts`: `readSettingsDeepLink(location): { section, anchor? } | null` — `section` must
  be a registry id (`findSection`), `anchor` must belong to that section, anything else is `null` /
  dropped (no throw, no tab). `applySettingsDeepLink()` calls `openSettings` and then removes the
  `settings` param and the hash with `history.replaceState`, so a reload does not reopen it on top of
  the restored layout.

## Tests (write first)
- `tests/canvas/settings-commands.test.ts`: one command per section and per anchor, ids unique;
  `matchCommands('passkey', …)` returns `settings.profile.account-security` (or the anchor that holds
  passkeys — read the registry); a label match outranks a keyword match; `readSettingsDeepLink` for a
  valid pair, an unknown section, an anchor from another section, an empty string.
- `tests/e2e/functional/settingsPalette.spec.mjs`: `>` + `notif` lists a Notifications settings
  command and Enter opens the Settings tab on that section; `mod+,` (Control+Comma in the test) opens
  the tab; `/?settings=profile#account-security` opens it with that anchor in the viewport and the URL
  no longer carries `settings`; `/?settings=nope` opens no Settings tab and logs no console error.
