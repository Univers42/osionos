## Why

- **A hug cell's height is never persisted.** `useHugHeights` measures the content and keeps the heights in React state only: "Heights are PRESENTATION state: they depend on this stage's rendered width and are never persisted" (`src/features/block-editor/ui/canvas/controller/useHugHeights.ts:25-30`). The stage applies them at render time and says why it refuses to write back: "this never writes back to the store (two panes at different widths would fight over persisted heights)" (`src/features/block-editor/ui/canvas/view/CanvasStage.tsx:56-62`). Consequence: the authored `frame.height` of a hug cell stays at its grid-derived value forever, so a reloaded page, an exported page and a second client all render the cell at the wrong height until the ResizeObserver fires again. The legacy editor had the opposite bug — it persisted `rowSpan` on every observer pulse and two panes at different widths overwrote each other in an infinite loop (`src/features/block-editor/ui/canvas/LayoutBlockEditor.tsx:204-209`).
- **There is no "Turn this page into a dashboard" action.** The page configuration menu has "Turn into wiki" (`src/entities/page/ui/PageHeaderBar.tsx:262-264`, guarded by `canToggleWiki` at `:191-192`) and "Remove header canvas" (`:267-273`), but nothing that turns an ordinary page into a canvas dashboard. The dashboard layout exists as a template (`src/features/block-editor/ui/canvas/model/templates.ts:45-48` → `createViewShowcaseCells()` in `src/widgets/database-view/model/databaseViewShowcase.ts:297`) and is reachable only from inside a canvas (the legacy toolbar button `src/features/block-editor/ui/canvas/LayoutBlockEditor.tsx:824-827`, the V2 templates menu `src/features/block-editor/ui/canvas/view/CanvasToolbar.tsx:55-79`). A user with a blank page has no way to get a dashboard.
- **A canvas cell cannot be shown or hidden by a formula.** `CanvasCell` (`src/features/block-editor/ui/canvas/model/types.ts:50-64`) and the persisted `LayoutCell` (`src/entities/block/model/types.ts:96-119`) carry no visibility field; the cell always renders. The Rust/WASM formula engine is already bridged for TypeScript — `compileFormula`, `evalFormula`, `evaluateHandle`, `batchEvaluate`, `validateFormula` (`src/shared/notion-database-sys/src/lib/engine/bridge.ts:97-197`, backed by the `#[wasm_bindgen]` exports in `src/shared/notion-database-sys/src/lib/engine/src/lib.rs:173-339`) — but the canvas never calls it. A dashboard author cannot make a cell appear only when `prop("status") == "active"`.

## Contract

### P4-4-a — save a hug height (do this one first)

1. **New persisted field `measuredHeight?: number`** on `CanvasCell` (`src/features/block-editor/ui/canvas/model/types.ts:50-64`) and on the persisted `LayoutCell` (`src/entities/block/model/types.ts:96-119`). Round-trip it in `migrate` (`src/features/block-editor/ui/canvas/model/migration.ts:60-86`) and `unmigrate` (`:88-109`) so it survives a save/reload. Accepted values: a finite number ≥ 0, rounded to whole px; anything else is dropped on migrate (fail to "no saved height").
2. **A new canvas action** `{ type: "setCellMeasuredHeight"; id: string; height: number }` (`src/features/block-editor/ui/canvas/model/types.ts:122-143`). The reducer (`src/features/block-editor/ui/canvas/model/canvasReducer.ts:30-97`):
   - sets `measuredHeight` on the cell;
   - sets `frame.height` to the same value;
   - **does not** push an undo entry — a measurement is not an authoring act (every other cell write goes through `withHistory`, `:63-64, :103-105`);
   - **is** persistable: add it to `PERSISTABLE_ACTIONS` (`src/features/block-editor/ui/canvas/model/canvasReducer.ts:24-28`) so the value is written through `buildCanvasBlockPatch` (`src/features/block-editor/ui/canvas/controller/persistence.ts:29-33`).
3. **Explicit, per-cell opt-in.** The cell inspector (`src/features/block-editor/ui/canvas/view/CanvasInspector.tsx:33-140`) gets a "Save measured height" control, rendered **only** when the cell's `sizing.height === "hug"` (`CanvasSizing` is `{ width, height }` with `"fixed" | "hug"`, `src/features/block-editor/ui/canvas/model/types.ts:36-39`). The control is disabled until a measurement for that cell exists. Clicking it dispatches action 2 with the height currently measured by `useHugHeights`.
4. **Saving freezes the cell.** A saved hug cell becomes `sizing.height = "fixed"` with `frame.height = measuredHeight`: the cell stops re-measuring and stops growing. A second inspector control, "Auto height" (the existing "Height constraint" segmented already offers `hug` at `src/features/block-editor/ui/canvas/view/CanvasInspector.tsx:76-81`), sets `sizing.height = "hug"` again and clears `measuredHeight`.
5. **On hydration**, a cell with `sizing.height === "hug"` and a valid `measuredHeight` gets `frame.height = measuredHeight` in `migrate` (`src/features/block-editor/ui/canvas/model/migration.ts:60-86`) so the first paint is already the right size. A cell without a saved height keeps its grid-derived height — today's behaviour, no backfill.
6. **Height only.** Width is never saved: the measurement is a `contentRect.height` at one rendered width. `Caveat:` must say a saved height is a snapshot of the width the cell was measured at; in a much wider or narrower pane the content re-measures and the cell changes size again (and the saved value becomes stale).
7. **Only hug cells are affected.** A fixed cell's `frame.height` is never rewritten by this action.
8. **Legacy editor compatibility.** The legacy editor's `LayoutCell` copy (`src/features/block-editor/ui/canvas/layout.types.ts:38-59`) gets the same optional field, and `layoutCellShellEqual` (`src/features/block-editor/ui/canvas/layout.helpers.ts:442-459`) must compare it — otherwise the legacy cell view does not re-render when only the height changes. `clampLayoutCell` already spreads the cell (`src/features/block-editor/ui/canvas/layout.helpers.ts:182-189`), so the field survives a legacy save.

### P4-4-b — "Turn this page into a dashboard"

1. **New page action `turn_into_dashboard`** in the `PageActionName` union (`src/services/page-actions/index.ts:24-40`).
2. **A pure builder** `turnIntoDashboard(page: PageEntry): Block` in `src/services/page-actions/index.ts` that returns one `layout` block:
   - `type: "layout"`, `layoutMode: "full_page"`, `layoutRole: "header"` — the same shape as the existing header band (`src/features/slash-commands/model/profileHeaderPreset.ts:94-115`);
   - `layoutCells` = `createViewShowcaseCells()` (`src/widgets/database-view/model/databaseViewShowcase.ts:297`) — the same definition the canvas "Dashboard" template uses (`src/features/block-editor/ui/canvas/model/templates.ts:45-48`), so the two paths cannot drift;
   - a `layoutConfig` with `columns: 12`, `rowHeight: 96`, `gap: 16`, `autoArrange: false`, `snapToGrid: true`, `preview: false` (a dashboard is edited, not previewed).
3. **Placement and idempotence.** The new layout block goes at **index 0** of the page content; the page's other blocks are kept and flow below it. If the page already has a `layout` block with `layoutRole: "header"`, that block is **replaced** by the new one — the action never stacks two dashboards. A second run on an already-dashboard page produces the same block list (same cell count, same first-cell id is not required — ids may be new).
4. **The write goes through the store, not a new API.** `usePageActions` (`src/entities/page/model/usePageActions.ts:332-363`) gains a `turnIntoDashboard` callback that: takes a version snapshot first (the existing `snapshot` helper, `:172-175`), computes the new content, calls `updatePageContent(pageId, next)` (`src/store/usePageStore.ts:353-368`), logs the action through the existing `logAction` (`:164-170`) and pushes a toast. The action is therefore undoable from the page's version history.
5. **The menu entry.** `src/entities/page/ui/PageHeaderBar.tsx:251-273` gains a `LayoutDashboard` item labelled "Turn into dashboard", placed next to "Remove header canvas". It is shown only when the page surface allows it — `page.surface` is `undefined | "page" | "agent" | "home"` (`src/entities/page/model/types.ts:75`); it is hidden for `"folder"`, `"wiki"`, `"code"` and `"app"`. It is hidden when the page is locked (`config.locked`, `src/entities/page/model/usePageActions.ts:187`).
6. **Security edge — who may call what.**
   - The write is refused by the store unless the caller may edit the body: `updatePageContent` returns early unless `canEditBody(page, getCurrentPageAccessContext())` (`src/store/usePageStore.ts:356`), and `canEditBody` = body loaded **and** `canEditPage` (`src/store/pageStore.helpers.ts:63-65`), which is the owner or a collaborator whose workspace role carries `update` (`src/shared/lib/auth/pageAccess.ts:270-286`). A viewer sees no menu item and the store refuses the write even if the item were forged.
   - A page **reader** sees the dashboard. Its cells embed live database view blocks; those views are the app's known seed databases, and the dashboard does not widen any read rule — the cell renders the view, the view's own data rules apply. Do not copy rows into the page content: the dashboard must stay a live view, never a snapshot of someone else's rows.
   - The action is recorded in the page's action log and synced to `/api/pages/:id/actions` only when `VITE_PAGE_ACTION_SYNC_ENABLED` is on (`src/services/page-actions/index.ts:22, :338-350`); no new bridge route is added by this package.

### P4-4-c — a cell shown or hidden by a formula

1. **New persisted field `visibilityFormula?: string`** on `CanvasCell` (`src/features/block-editor/ui/canvas/model/types.ts:50-64`) and on the persisted `LayoutCell` (`src/entities/block/model/types.ts:96-119`); round-trip it in `migrate`/`unmigrate` (`src/features/block-editor/ui/canvas/model/migration.ts:60-109`) exactly like `measuredHeight`. Empty string and `undefined` both mean "always visible".
2. **Call the engine; never edit it.** The engine is the Rust/WASM module under `src/shared/notion-database-sys/src/lib/engine` — a submodule with its own toolchain. Use only the existing TypeScript bridge (`src/shared/notion-database-sys/src/lib/engine/bridge.ts`): `evalFormula(formula, props)` (`:118-128`) to evaluate, `validateFormula(formula)` (`:175-183`) to validate. Do not modify anything under `src/shared/notion-database-sys/**`.
3. **The formula's context is the page's own properties.** `props` is a `PropertyMap` (`src/shared/notion-database-sys/src/lib/engine/bridgeTypes.ts:45`): `key → value`, built from `PageEntry.properties` (`src/entities/page/model/types.ts:41-48`) with the same lookup the header slots use (`src/pages/notion-page/model/headerBinding.ts:19-27`). Values are converted by the engine's own `toJsonValue` (`bridgeTypes.ts:47-55`), so a string, a number, a boolean and an array all work; a `multi_select` value arrives as an array.
4. **Truthiness.** The cell is visible when the result is not falsy. Falsy = `false`, `0`, `""`, `null`/`undefined`. The engine-unavailable sentinel `FORMULA_ENGINE_UNAVAILABLE` (`src/shared/notion-database-sys/src/lib/engine/bridge.ts:59`) means **visible** — the package fails open, never hides content because the engine did not load.
5. **A new pure helper** `evaluateCellVisibility(formula: string | undefined, props: PropertyMap): boolean` in a new file `src/features/block-editor/ui/canvas/model/visibility.ts`. It must be side-effect free and unit-testable without a DOM.
6. **The hidden cell is not rendered, but it is not deleted.** The cell stays in the canvas store, so the inspector can still select it and edit the formula, and undo restores it. The stage filters the render list (`src/features/block-editor/ui/canvas/view/CanvasStage.tsx:107-129`); the cell's chrome, editor and resize handles are all absent from the DOM.
7. **Re-evaluation on property change.** The canvas must re-evaluate when a page property changes. The properties live in the page store and are written by `usePageProperties` (`src/pages/notion-page/ui/usePageProperties.ts:26-37`). Concrete mechanism: `CanvasRoot` (`src/features/block-editor/ui/canvas/view/CanvasRoot.tsx:41-159`) reads the page's `properties` from `usePageStore` and passes them to `CanvasStage`, which passes them to the cell view; a property edit therefore re-renders the canvas and re-evaluates every formula.
8. **Inspector UI.** `src/features/block-editor/ui/canvas/view/CanvasInspector.tsx` gets a "Visibility formula" text field with a "Check" action that calls `validateFormula` and prints the first error message inline (`ValidateResult.errors[0].message`, `bridgeTypes.ts:29-32`). An invalid formula leaves the cell **visible** and the error is shown in the inspector, never as a toast. The field is empty by default.
9. **Security edge — who may call what, and what a non-owner sees.**
   - The formula runs in the reader's own browser, against the page's own property values, and never leaves the page. There is no server call and no cross-page read.
   - A reader of the page sees exactly the cells whose formula is true **for them**. Today `PageEntry.properties` has no per-property ACL (`src/entities/page/model/types.ts:41-48`) and the page ACL is page-level (`src/shared/lib/auth/pageAccess.ts:245-253`), so every reader of a page sees the same property values and therefore the same visibility. The `Caveat:` must say that a formula which branches on a value leaks that value's existence to every reader of the page — so a formula may only reference properties the page already exposes to all of its readers.
   - The formula text itself is stored in the page's block JSON and is readable by anyone who can read the page. It is authoring metadata, like the cell label.
   - A viewer (no edit right) gets no inspector and cannot set a formula; the field is only reachable from the canvas inspector, which only opens for editors.

## Decisions (orchestrator, 2026-10-22, from the drafter's open questions)
1. **Freeze.** "Save measured height" sets `sizing.height = "fixed"` with the measured value, as item
   4 says; "Auto height" undoes it.
2. **Per cell.** No canvas-level flag: it would bring back the two-panes fight
   (`CanvasStage.tsx:56-58`).
3. **The page's own properties** are the formula's context. Binding a cell to a database record is
   a later package (it changes the security edge).
4. **Re-evaluate on every render** with new properties. Dependency-narrowed invalidation is not
   needed for the first cut.
5. **The existing "Dashboard" template** (`createViewShowcaseCells()`), so the two paths cannot
   drift. P4-1's `sys:` sources (the user's own data) replace its cells later. Say so in a comment
   at the builder.
6. **`surface` unchanged.** A dashboard is a full-page layout block, not a new surface.
