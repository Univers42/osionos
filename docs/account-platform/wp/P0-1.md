# P0-1 — account-plane database foundation (root groot repo)

**This package runs in the ROOT groot repo** (your worktree root has `models/`, `scripts/`,
`apps/grobase/`), not in the osionos app. From `COMMON.md`, the Scope, Code (comments, `Caveat:`,
no TODO), Tests and Finish rules apply; its Environment section does not: here you run `sh` and
`docker` directly. SQL files in `models/` carry no 42 header — copy the comment-header style of
`models/auth-session-cutoffs.sql`. Shell scripts keep their existing header.

## Why
Account data (sessions now; profiles, settings, emails in P1-1) will be read by the bridge with a
per-user JWT, and Postgres row-level security will keep each user to their own rows. The auth
contract is `docs/account-platform/adr/0001-account-jwt.md` in the osionos app (copied below
where it matters). This package creates the role, the uid helper, the first account-plane table
(`osionos_sessions`), the audit columns the bridge guard will write, and two indexes whose absence
makes today's queries sequential scans. Nothing reads these objects yet.

## The migration — exact contract
One transaction (`BEGIN; … COMMIT;`), fully idempotent (a second run changes nothing — check `g`).
Every index is NAMED and `IF NOT EXISTS` (an unnamed `CREATE INDEX` makes a duplicate on every boot).

1. **Role** (in a `DO` block, guarded by `pg_roles`):
   `CREATE ROLE osionos_account_user NOLOGIN NOINHERIT NOBYPASSRLS;` when absent.
   When role `authenticator` exists and `NOT pg_has_role('authenticator','osionos_account_user','MEMBER')`:
   `GRANT osionos_account_user TO authenticator;` (PostgREST must be allowed to switch to it).
   `GRANT USAGE ON SCHEMA public TO osionos_account_user;`
2. **uid helper** — exactly:
   ```sql
   CREATE OR REPLACE FUNCTION public.osionos_account_uid() RETURNS uuid
     LANGUAGE sql STABLE SET search_path = pg_catalog AS $$
     SELECT CASE
       WHEN current_user = 'osionos_account_user'
        AND c ->> 'role' = 'osionos_account_user'
        AND c ->> 'aud' = 'osionos-account'
        AND c ->> 'sub' ~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
       THEN (c ->> 'sub')::uuid END
     FROM (SELECT NULLIF(current_setting('request.jwt.claims', true), '')::jsonb AS c) AS s
   $$;
   REVOKE ALL ON FUNCTION public.osionos_account_uid() FROM PUBLIC;
   GRANT EXECUTE ON FUNCTION public.osionos_account_uid() TO osionos_account_user, service_role;
   ```
   Comment above it: the ROLE is the boundary (GoTrue never issues `osionos_account_user`; a client
   can pick `aud`), every condition fails closed to NULL (an array `aud`, an upper-case or malformed
   `sub` → NULL, never an error), and it is NOT `SECURITY DEFINER`.
3. **`public.osionos_sessions`** — one row per sign-in, keyed by the app token's `jti`:
   ```sql
   id UUID PRIMARY KEY,                                   -- the osionos_v1 token jti
   user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
   created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
   expires_at TIMESTAMPTZ NOT NULL,
   last_seen_at TIMESTAMPTZ NOT NULL DEFAULT now(),
   auth_method TEXT NOT NULL CHECK (auth_method IN ('password','email_otp','passkey','oauth','handoff','refresh')),
   ip_prefix CIDR CHECK (ip_prefix IS NULL OR (family(ip_prefix) = 4 AND masklen(ip_prefix) <= 24)
                                           OR (family(ip_prefix) = 6 AND masklen(ip_prefix) <= 48)),
   ip_hash TEXT CHECK (ip_hash IS NULL OR ip_hash ~ '^[0-9a-f]{64}$'),
   user_agent TEXT CHECK (user_agent IS NULL OR char_length(user_agent) <= 256),
   sudo_until TIMESTAMPTZ,
   refresh_hash TEXT CHECK (refresh_hash IS NULL OR refresh_hash ~ '^[0-9a-f]{64}$'),
   family_id UUID,
   parent_id UUID,
   revoked_at TIMESTAMPTZ,
   revoked_reason TEXT CHECK (revoked_reason IN ('user','admin','logout_all','password_change','refresh_reuse','deletion')),
   CHECK (expires_at > created_at),
   CHECK ((revoked_at IS NULL) = (revoked_reason IS NULL))
   ```
   The `ip_prefix` CHECK is how "a raw IP is never stored" is enforced by the database (a /32 is refused).
   Indexes: `osionos_sessions_user_active_idx (user_id, created_at DESC) WHERE revoked_at IS NULL`,
   `osionos_sessions_revoked_idx (revoked_at) WHERE revoked_at IS NOT NULL` (the revocation delta poll),
   `osionos_sessions_expires_idx (expires_at)` (the reaper).
   `DROP TRIGGER IF EXISTS osionos_sessions_realtime_trigger ON public.osionos_sessions;` — grobase's
   CREATE TABLE hook (`apps/grobase/scripts/migrations/postgresql/012_realtime_triggers_all_tables.sql:64`)
   would broadcast every row, `ip_hash` and `refresh_hash` included.
   Grants and RLS:
   ```sql
   ALTER TABLE public.osionos_sessions ENABLE ROW LEVEL SECURITY;
   REVOKE ALL ON public.osionos_sessions FROM PUBLIC, anon, authenticated;
   GRANT ALL ON public.osionos_sessions TO service_role;
   GRANT SELECT (id, created_at, expires_at, last_seen_at, auth_method, ip_prefix, user_agent, revoked_at, revoked_reason)
     ON public.osionos_sessions TO osionos_account_user;
   DROP POLICY IF EXISTS osionos_sessions_service_role_all ON public.osionos_sessions;
   CREATE POLICY osionos_sessions_service_role_all ON public.osionos_sessions FOR ALL TO service_role USING (true) WITH CHECK (true);
   DROP POLICY IF EXISTS osionos_sessions_owner_read ON public.osionos_sessions;
   CREATE POLICY osionos_sessions_owner_read ON public.osionos_sessions FOR SELECT TO osionos_account_user
     USING (user_id = (SELECT public.osionos_account_uid()));
   COMMENT ON TABLE public.osionos_sessions IS 'osionos:account-plane';
   ```
   `(SELECT public.osionos_account_uid())` is deliberate: wrapped, it is evaluated once per query
   (an InitPlan); bare, once per row. Say so in a comment. The `COMMENT` is the marker the grants
   checks read; every account-plane table carries it. Column grants mean the role can never
   `select=*` (PostgREST answers 42501): callers name their columns. Say so in a comment.
4. **Audit columns** on `public.osionos_bridge_audit_events` (one `ALTER TABLE … ADD COLUMN IF NOT EXISTS` each):
   `actor_id UUID`, `session_id UUID`, `ip_hash TEXT CHECK (ip_hash IS NULL OR ip_hash ~ '^[0-9a-f]{64}$')`,
   `user_agent TEXT CHECK (user_agent IS NULL OR char_length(user_agent) <= 256)`; index
   `osionos_bridge_audit_events_actor_idx (actor_id, created_at DESC) WHERE actor_id IS NOT NULL`.
   No FK on `actor_id`: audit rows must outlive a deleted user.
5. **Missing indexes**: `osionos_bridge_identities_email_hash_idx ON public.osionos_bridge_identities (email_hash)`
   (queried by `email_hash=eq.` in the osionos bridge, `scripts/bridge-api.mjs:1539,1543` of the app — a
   seq scan today); `osionos_feed_shares_user_target_idx ON public.osionos_feed_shares (user_id, target, created_at DESC)`
   (the profile feed query `user_id=eq.…&target=in.(profile)&order=created_at.desc`, app `scripts/bridge-profile.mjs:231`).
   Add a `Caveat:` line: plain `CREATE INDEX` takes a write lock for its duration — fine at today's
   row counts (both tables are small), wrong for a table with millions of rows (then build it
   `CONCURRENTLY` outside this transaction).
6. `NOTIFY pgrst, 'reload schema';` before `COMMIT`.
7. A manual `-- DOWN` comment block at the end, in reverse order: drop the policies, the table, the
