# P1-3b — Settings becomes a workspace tab, driven by one section registry

Depends on P1-3a (panels already split into `src/features/settings/<section>/…Panel.tsx`).
Read `CLAUDE.md` §Architecture ("No react-router", the `tab.kind` guard chain, the two
"open page" sources of truth) before touching the tab plumbing.

## Goal
Settings stops being a modal. It is a pane tab (`tab.kind: "settings"`) that any surface opens or
focuses with one call, `openSettings(section?, anchor?)`. One registry is the only list of
sections: navigation, search, titles and panel loading all read it. Each panel is its own lazy
chunk. The modal and its three private copies (App, UserSwitcherPanel, SidebarFooter) are gone.

## Contracts
**Registry — `model/sections.ts`** (no React rendering in this file; lucide icon references are fine):
- `SettingsSectionId`: the same 19 string ids as today (`profile` … `shortcuts`, see the current
  `tabGroups` in `SettingsCenter.tsx`), so saved links and `menus.ts` callers keep their meaning.
- `SETTINGS_GROUPS` (Account, Workspace, Features, Access & billing — same order and labels as today) and
  `SETTINGS_SECTIONS`: per section `id`, `group`, nav `label`, `title`, `subtitle` (today's `prompts`), `icon`,
  and `anchors` (`{ id, label, keywords, description? }`) — the anchor data MOVES here from
  `packages/osionos-ui/src/primitives/useSettingsSearchIndex.ts:42-89` (copy it; leave the package alone).
- `findSection(id: string)` and `searchSettings(query)` → `{ section, anchor }[]` with today's scoring
  (`useSettingsSearchIndex.ts:91-115`: label prefix +4, any haystack hit +1, ties by label).
**Panels — `ui/sectionPanels.tsx`**: `Record<SettingsSectionId, LazyExoticComponent<ComponentType<SettingsPanelProps>>>`,
one `React.lazy(() => import('<deep path>').then(m => ({ default: … })))` per section, adapting the
uniform `SettingsPanelProps` (`activeUserId`, `persona`, `workspaceId`, `workspaceName`, `members`)
to each panel's current props. `Record` makes a missing section a type error. Deep import paths only.
**Navigation — `model/settingsNav.ts`**: a zustand store `{ section, anchor }` (default section
`profile`, not persisted) and `openSettings(section = 'profile', anchor?)` which sets the store and
calls `useWorkspaceLayout.getState().openTab(settingsTab())` (features already import
`@/widgets/workspace-grid/model/*` directly, e.g. `features/marketplace/model/marketplaceActions.ts`).
**Tab plumbing**: `"settings"` in `TabKind`; `SETTINGS_TAB_ID = "__settings__"` and `settingsTab()` in
`layoutPersist.ts` following `adminTab()` (title `Settings`, an icon `IconValueView` resolves —
check `packages/osionos-ui` for the name); add `"settings"` to the no-page list in `layoutSync.ts:21`
(else focusing the tab rewrites `activePage`); a guard in `PaneContent.tsx` shaped like the console
guard (ErrorBoundary › Suspense › view), loading `LazySettingsView` from `lazyViews.tsx`.
**Callers**: App keeps no settings state; it passes `openSettings` where it passed its local
function. `menus.ts`/`TopBar.tsx` type the argument as `SettingsSectionId`. UserSwitcherPanel and
SidebarFooter call `openSettings('general' | 'people')` and close their own popover; their
`LazySettingsCenter` copies go.

## The view — `ui/SettingsView.tsx` (design rules; tokens only, no new colours or fonts)
- Root `<div role="region" aria-label="Settings">` filling the pane. Two columns when the PANE is
  wide, a horizontal section strip above the panel when it is narrow: use a container query
  (Tailwind v4 `@container` + `@…:` variants), not a viewport breakpoint — a split pane at 1440 px can be 480 px wide.
- Section nav: `<nav aria-label="Settings sections">` with the group labels and one `<button>` per
  section; the active one has `aria-current="page"`. Not `role="tab"`: the workspace tab strip is
  made of tabs, and a list of sections is navigation. Visible focus ring; at least 44 px tall under
  `pointer: coarse`. Keep the current look (icon + label, the profile entry shows the persona avatar/name)
  and the "Get osionos AI" footer.
- Search: inside `role="search"`, an `<input type="search" aria-label="Search settings">` (today it has a
  placeholder only — an unlabeled field). Results as today (max 8, Enter opens the first); Escape clears.
- Header: `<h1>` = section title, subtitle below; `Section` in `settingsKit.tsx` renders `<h2>` instead
  of `<h3>` (same classes) so the outline has no gap.
- Body: `<Suspense>` with a skeleton the height of a few rows (no layout jump), then the lazy panel.
- Anchor: when the store holds an anchor, after the panel renders scroll
  `[data-settings-anchor="<id>"]` into view and flash the same ring classes as today
  (`SettingsCenter.tsx` `openSearchResult`), then clear the store's anchor. Query INSIDE the view
  root, never `document` — other panes may render the same markup.
- No close button: the tab strip closes the tab (its button is labelled `Close Settings`).
