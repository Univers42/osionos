# Phase-0 spike: VS Code's services in editor mode against a VS Code server (2026-10-30)

Verdict: **KEEP**. All 7 keep-or-kill checks passed, on this laptop and on the grobase VM
reached over `ssh -L`. Throwaway code: `~/.cache/osionos-wt/vscode-spike` (owner's machine),
driven headless by Playwright. Decision record: groot `docs/ide/ADR-006-vscode-backend-osionos-host.md`.

## Setup

- **Client:** `@codingame/monaco-vscode-api` 37.6.1, with these service overrides and no views:
  - remote-agent, files, editor (our own `openEditor`), terminal (remote backend), scm, debug,
    markers, search, extensions + Open VSX gallery, textmate, theme, and the base services.
- **Server:** code-server v4.138.0's bare VS Code server, run as `lib/node lib/vscode/out/server-main.js`.
  - It binds to 127.0.0.1 and reads a `--connection-token-file` at mode 0600.
  - The client sends `productConfiguration.commit = 59c988c7…`, the server's build commit.
- **Same-origin proxy (prototype of the bridge proxy):** server paths `/stable-<commit>/…`, plus
  upgrades carrying `reconnectionToken`, go to the server; everything else goes to Vite.
- **Extensions from Open VSX:** `ms-python.debugpy` 2026.6.0 and `detachhead.basedpyright` 1.40.2.
  The server pulled `ms-python.python` itself.

## What broke on the way (now constraints)

1. **`enableWorkerExtensionHost: true` without an iframe domain hangs every `executeCommand`.**
   Commands await activation on all hosts, including one that never starts. Keep it off.
2. **The server sends no CORS headers, but the browser fetches its extension resources directly.**
   A same-origin proxy is required.
3. **code-server's `bin/code-server-oss` launcher expects `lib/vscode/node`, which isn't there.**
   The node daemon calls `server-main.js` with the bundled Node instead.
4. **The terminal's default shell is the server's `$SHELL`.** The daemon must start it with the
   user's login shell.
5. **`@xterm/addon-ligatures` pulls Node built-ins into the browser build.**
   It is stubbed; ligatures are off by default.

## Caveats

- **These are local-network numbers from one laptop and one VM.**
  A remote tunnel adds round trips to checks 1–6.
- **Check 6 used the unbundled dev server.** The production build is expected to be faster,
  but that is not measured.
