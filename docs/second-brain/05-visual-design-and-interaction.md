# Second Brain — Visual Design & Interaction (05 / 8)

> Owns **"outstanding & beautiful, better than Obsidian."** Beauty here is not
> decoration — it's *legibility at scale*. A 10k-node graph that's pretty but
> unreadable has failed. Every visual choice below earns its place by making
> structure or meaning clearer.

---

## 1. Design principles

1. **Color encodes meaning, not mood.** Hue = which database. Notes = one
   reserved color. Nothing is colored arbitrarily.
2. **Calm by default, loud on focus.** At rest the graph is low-contrast and
   restful; interaction (hover/select/search) raises contrast *locally*.
3. **Progressive disclosure.** Overview shows shape; zoom reveals labels; click
   reveals the record. You're never shown everything at once.
4. **Respect the data identity.** Promoting a record to a note must never hide
   that it's still that database row (the brief: data-first).
5. **Theme-native.** Reuse the existing `--osio-*` token system so the graph is
   light/dark-correct and consistent with the rest of osionos.

---

## 2. Color system (data vs note — the headline requirement)

```
record node  → databaseColor(databaseId)   // generated palette, doc 01 §3
note node    → --osio-note  (one reserved, unmistakable hue, e.g. warm amber)
tag hub      → neutral/desaturated (structural, not data)
database hub → databaseColor, larger, ringed
```

- **Notes are visibly "another color"** vs data, per the brief — a single
  reserved note hue across the whole graph, so your eye instantly separates
  "knowledge I wrote" from "data I have."
- **A record that has a note** keeps its database color but gains a thin note-hue
  ring + a small dog-ear/badge → it reads as "data, annotated," not "converted."
- Palette generated by golden-angle hue rotation keyed on `databaseId` →
  distinct, stable, supports *any* number of backends (fixes today's 6-color
  hard-coded `NODE_COLORS`).
- Accessibility: hues are paired with shape/badge cues (note ring, tag diamond,
  database ring) so color isn't the *only* channel; contrast checked in both
  themes.

```
   ● record (db A)     ◍ record with note      ◆ tag hub      ⬢ database hub
   ● record (db B)     ★ note (reserved hue)   ┄┄ tag edge    ── relation edge →
```

## 3. Node & edge styling (Canvas2D, doc 04)

**Nodes**
- Radius from `weight` (degree + value), floored for tap-ability, capped so hubs
  don't dominate.
- Soft inner gradient + 1px outer stroke at mid/near zoom for depth; flat dots at
  far zoom (LOD, doc 04).
- States: `default`, `hover` (subtle lift + label), `selected` (ring in accent),
  `related` (kept full-contrast during focus dimming), `pending` (doc 02 —
  dashed ring / reduced opacity), `dimmed` (focus mode background).

**Edges**
- `relation` → solid, slight curve, arrowhead if directed; weight = `strength`.
- `tag` → dashed, thinner, secondary color (associative, not structural).
- `note_of` → note-hue, dotted (provenance link).
- `note_link` → note-hue, solid (wikilink between notes).
- **Edge bundling (phase 2):** hub-and-spoke clusters get gentle curve bundling
  to reduce hairball density — a key "better than Obsidian" legibility win at
  scale. Documented as a phase-2 enhancement once the engine is proven.

---

## 4. Focus & neighborhood (the core interaction)

- **Hover** a node → its 1-hop neighborhood stays full-contrast, everything else
  dims (`focusDimming` selector, doc 01) → instantly see "what connects to this."
- **Click** → select: opens the inspector (§6), pins focus, frames camera on the
  neighborhood (doc 04 focus-node animation).
- **Double-click** → expand: pull in 2-hop neighbors (lazy, for huge graphs).
- **Drag** → reposition (pins node in worker; doc 04 pin/unpin protocol).
- Focus dimming is local and cheap (adjacency lookup), so it stays 60fps even at
  10k.

---

## 5. Navigation & wayfinding at scale

- **Minimap** (`ui/Minimap.tsx`) — a culled, dot-only overview with a viewport
  rectangle; click/drag to jump. Essential when 10k nodes exceed the viewport.
- **Search** (`ui/GraphToolbar.tsx`) — prefix search over the doc-01 search index;
  results highlight + camera-fly to the match; `/` to focus, arrows to cycle.
- **Filters** — legend doubles as filters: toggle a database on/off (uses
  `filterByDatabase`, id-level, no graph copy), toggle edge kinds (relation/tag),
  toggle "notes only" / "data only".
- **Cluster by database** — optional force grouping so each database forms a
  loose region (generalizes today's `nodeCenter` per-kind anchors into per-db
  anchors) → the graph reads as a map of your data domains.

---

## 6. The inspector (`ui/NodeInspector.tsx`) — click-through to the record

This is where "each node is clickable" pays off. Selecting a node opens a side
panel showing the **actual record**, not a lossy summary:

- Header: label, database (colored chip), source backend, version.
- **Properties** — the record's fields (lazy-hydrated, doc 02 §8), editable
  inline; edits route through `commitTxn` (doc 02) with optimistic echo.
- **Relations** — grouped by relation/tag; each is a clickable chip that
  selects/flies-to the related node (replaces today's relation buttons, but
  graph-native).
- **Actions** — `Open as page`, **`Convert to note` / `Open note`** (doc 06),
  `Add relation`, `Add tag` (doc 03), `Copy id`.
- A record with a note shows the note inline/expandable; a note node shows its
  source record link (provenance).

The inspector is the only heavy React in the feature, and it renders only for
the *selected* node — so it's free at rest.

---

## 7. Motion & polish (tasteful, bounded)

- Camera moves and focus dimming animate with short eased transitions
  (`prefers-reduced-motion` respected → instant).
- New nodes fade/scale in from their seed position (doc 04 node reuse).
- Physics settle is visible but quick (alpha decay tuned, doc 04) — the graph
  "breathes" into place, then goes still and silent (no idle CPU).
- No gratuitous continuous animation — calm by default (principle 2).

---

## 8. Empty / loading / error states

- **Empty** (no databases / all filtered out): a friendly prompt to enable a
  source or clear filters — not a blank canvas.
- **Loading** large data: progressive — render nodes as they derive; skeleton
  minimap; never a frozen white screen.
- **Pending/failed writes** (doc 02): inline node treatment + non-blocking toast.
- **Edge circuit-breaker tripped** (doc 03): a quiet toolbar notice explaining
  tag edges were collapsed to hubs for performance.

---

## 9. Accessibility & input

- Full keyboard model: pan/zoom (today's keys, ported), `Tab`/arrows to move
  selection along edges, `Enter` to inspect, `/` to search.
- Selected-node state is announced (aria-live) with label + relation count.
- Canvas has an offscreen DOM mirror of the *selected* node + its relations for
  screen readers (the whole 10k graph isn't announced — that would be useless;
  the focused subgraph is).
- Hit targets floored to a tap-friendly minimum (doc 04 radius floor).
