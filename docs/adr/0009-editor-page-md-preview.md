# 0009. Editor page .md/.omd preview and the Ctrl/Cmd+Shift+V toggle

Date: 2026-11-07. Status: accepted — devil PROCEED-WITH-CONDITIONS (EP1–EP14, addendum EP15–EP31). Follows [0008](0008-quota-aware-failover.md).

## Verdict: PROCEED-WITH-CONDITIONS (EP1–EP14)

No script-execution path into the credentialed node origin was found. The real risks are other things: a relative-link click navigates the editor frame away and loses unsaved edits, a measured parser stack overflow unmounts Monaco, the app's global shortcut dispatcher swallows the toggle, and the preview re-parses on every cursor move. Every one has a check.

| Axis | Score | Why |
| --- | --- | --- |
| Blast radius | 3 | every node user's local-file editor + the app's IDE code view; not system-wide |
| Reversibility | 3 | app: revert/redeploy. node-pages: main-only publish, `--clobber` single asset (`.github/workflows/node-pages.yml:5-7,47`); nodes recover only on their next update (`packages/osionos-node/install.sh:68-75`) |
| Cost on failure | **3 (worst)** | unsaved local edits lost (in-frame navigation, no `beforeunload` in `src/editor-client`; render crash). Tab frozen for seconds on a pathological file. No credential leak path found |
| Confidence | 3 | XSS closed by 3 layers (below). Unverified: toggle-to-paint at 8 MiB, the editor alias, the shortcut under the dispatcher |

## Steel-man

The preview adds no authority. The engine has no host imports and no `fetch`/`WebSocket`/storage calls (`rg` over `packages/markdown-engine/{markdown,renderCore.ts,react.tsx}`: empty). Raw HTML is closed three times over: `allowHtml: false` default (`markdown/renderers/react.tsx:91`, html_block → `<pre><code>` at 320-326); `sanitizeUrl` drops every scheme except http/https/mailto/tel/page after stripping control chars (`renderCore.ts:108-125`); and the editor CSP `script-src 'self'`, no inline (`packages/osionos-node/static-client.mjs:49-57`), blocks `javascript:` even if both of the others failed. F2 (`vite.editor.config.ts:24-27,36-46`) still fails the build if the shared component ever pulls in RawPreviewPane/entities, CI included (`node-pages.yml:36`).

## Facts (measured 2026-11-07, `node --experimental-strip-types --experimental-loader tests/canvas/ts-extension-loader.mjs`, engine `parse()` from `markdown/parser.ts`)

- F1 Nested list, 2-space steps. Depth 1000 (1.0 MB) parses in 137.6 ms. **Depth 2000 (4,005,999 chars) throws `RangeError: Maximum call stack size exceeded`**, and so does depth 2800 (7.8 MB). Both are under the editor's 8 MiB cap (`src/editor-client/FileView.tsx:166`). No error boundary exists anywhere in `src` (rg `getDerivedStateFromError|componentDidCatch`: none outside notion-database-sys).
- F2 Unclosed `[` runs scale quadratically: 25k 406 ms · 50k 1600 ms · 100k 6080 ms · 50k across 500 lines 2381 ms. At 1 MiB, **estimated** ~10 min (extrapolation, not run).
- F3 Normal content (testing_markdown.md repeated): 1 MiB 34–48 ms, 8 MiB 260 ms per parse. `MarkdownView` parses inside render with no memo (`react.tsx:124`). The editor re-renders on every cursor move (`onStatus` → `setStatus`, `FileView.tsx:79-80`). The old app pane memoised (`MarkdownPreviewSplit.tsx:35`).
- F4 A link with no scheme passes `sanitizeUrl` unchanged (`renderCore.ts:114`). `isExternalUrl` is true only for http(s) (`renderCore.ts:104-106`). So `docs/a.md`, `/api/...` and `//evil.example` become in-frame hrefs. The editor iframe has no sandbox (`src/features/machines/ui/MachineFileTab.tsx:31`) and the app sets no frame-src (`public/_headers:7`, `docker/services/node/nginx.conf:22`). A click therefore navigates the "File on this computer" frame: unsaved Monaco text is gone, or an attacker page renders inside app chrome with no URL bar.
- F5 Mention links emit `<img src="${origin}/favicon.ico">` unconditionally (`reactHelpers.tsx:228,241-249`, `linkMention.ts:37`), and MarkdownView has no option to turn it off. External, relative and root-relative images become `<img>` (`reactHelpers.tsx:273-285`). CSP blocks the remote ones (console violations). Relative ones hit the node origin: a 404, or `/api/node/<id>/…`, which is cookie-authenticated and forwarded (`ide-origin.mjs:156-183`).
- F6 The engine already strips front matter: `parse()` emits a `front_matter` node (`parser.ts:51-59,68-83`) and the React renderer has no case for it, so it renders an empty Fragment (`react.tsx:398`). `joinFrontMatter` output (one JSON value per line, `frontMatter.ts:42-62`) always matches that fence. The step-4 move is unnecessary.
- F7 The app's dispatcher is on document **capture** (`useAutomationDispatcher.ts:122`, mounted `src/app/App.tsx:212`). `paste-plain` is `mod+shift+v` / `notInText` (`defaultAutomations.ts:21`) and `pastePlain` has no `enabled` (`clipboardCommands.ts:15`), so `runCommand` calls preventDefault + stopImmediatePropagation (`useAutomationDispatcher.ts:67-68`) before React's `onKeyDownCapture`. A focused preview `div` is "not in text", so the toggle back is dead. The escape hatch is `[aria-keyshortcuts]` (`useAutomationDispatcher.ts:106-109`, `combo.ts:31-47`).
- F8 `useMarkdownPreview` resets the source whenever the identity of `readInitialText` changes (`MarkdownPreviewSplit.tsx:48-51`). FileView passes an inline `() => loaded.text` (`FileView.tsx:77`). The same pattern in the hook is a render-phase setState loop.
- F9 With Shift held, `e.key` is `'V'`. The plan's `e.key 'v'` never matches.
- F10 The editor vite config aliases only `@osionos/ui` and `'@'` (`vite.editor.config.ts:57-59`). There is no `node_modules/@osionos`. The main config shows the markdown-engine regexes must sit above `'@'` (`vite.config.ts:113-150`).

## Alternatives considered

- **Move `frontMatter.ts` into `ide/model`** (the plan's step 4): it churns 6 importers (codec, materialize, inboundPlanWrite ×2, 2 tests, 1 bench) and misplaces a page-file format primitive, all to solve what the engine already does (F6). Rejected.
- **A single-file exception in F2's `BANNED`**: it weakens the one mechanical guard to save nothing (F6). Rejected.
- **RawPreviewPane in the editor page**: it imports entities. F2 fails the build by design. Rejected.
- **Let the node serve local images for preview**: a new fs-read surface outside the credentialed socket. Not requested. Do not add it.

## Consequences

- The app's .md preview becomes plain Markdown (requested). .omd keeps the block look in the app only.
- Unclosed-bracket input stays slow until the engine issue (EP7) lands. A preview off by default bounds the exposure.
- Rollback: revert on main, re-run node-pages, and nodes pick it up on their next update. Rolling back the app needs only the redeploy.

## Addendum 2026-11-07: delta D1 (engine emphasis hoist) + D2 (preview parse in a Web Worker), EP15–EP31

Tree read (read only): worktree `/mnt/storage/dlesieur/wt/osionos-md-shortcut`, branch feat/md-preview-shortcut, engine submodule pinned 4269ee92 (heads/main). My measurements ran locally on node v26.13.0, i5-13600KF, with copies of the engine in a scratchpad (`orig` = 4269ee92, `d1` = 4269ee92 plus the hoist). No source file was edited. The builder's numbers came from node 22 and are slower in absolute terms (orig N=5000: 6054 ms there, 1061 ms here).

### Verdict: PROCEED-WITH-CONDITIONS (EP15–EP31)

D1 is semantics-identical. The proof is below and a differential run backs it. D1 is also the only part of the delta that reaches the app's main-thread consumers. D2 is sound in outline and is what actually bounds the preview. As specified, though, D2 has three holes: F2 cannot see inside the worker bundle; a depth class of documents parses but cannot cross postMessage; and "supersede" is not defined. Each hole has a check below.

| Axis | Score | Why |
| --- | --- | --- |
| Blast radius | 4 (D1) / 2 (D2) | D1 changes `parseInline`, and the whole app runs that: page blocks, channel messages, the editor's serialize round-trip (`index.ts:45`, "`serialize(parse(x))` is a fixed point"). D2 is the preview only |
| Reversibility | 2 (D1) / 3 (D2) | D1: re-pin the submodule. D2: node-pages is a main-only publish, as before |
| Cost on failure | **4 (worst, D1)** | a semantic slip in D1 would be silent: `inlineTextEditing.ts:53` and `inlineFormatting.ts:81` parse, then re-serialize, so stored page text could be rewritten on edit. D2 failing gives a stuck or blank preview, a leaked worker burning a core, or a blind F2 |
| Confidence | 2 (D1) / 3 (D2) | D1 is proven (below). D2's worker-side stack and clone limits in Chromium are unmeasured. Node is not the browser |

### Steel-man

The parser is pure and DOM-free (README "Entry points"). Its AST is plain data. A worker with a kill timer is the only mechanism that bounds a parser whose worst case is still super-linear after any local fix. The editor CSP already admits same-origin workers, and Monaco's worker already ships from `/editor/assets/` in the current build.

### Facts (measured 2026-11-07 unless cited)

- G1 **D1 identity, proof.** Every write to `cursor` inside the loop (`parserInlineMatchers.ts:540-597`) is non-decreasing: `escape + 2` with `escape ≥ cursor`; `skipCodeSpan(text, backtick) > backtick ≥ cursor`; `next ≥ cursor`; `+= runLen` and `+= take` with both ≥ 1 (`remaining > 0` and `text[cursor] === marker`). Let `c = indexOf(ch, c0)` be cached at some `c0 ≤ cursor`. If `c === -1`, nothing at or after `c0` matches, so `indexOf(ch, cursor) === -1`. If `c ≥ cursor`, nothing matches in `[c0, c)` and `text[c] === ch`, so `indexOf(ch, cursor) === c`. Recomputing only when `c !== -1 && c < cursor` therefore yields, at every use, the value lines 547-548 compute today. `text` is an immutable string, and the caches must be per-call locals.
- G2 **D1 differential.** A `d1` copy with lazy caches (sentinel -2, recompute iff `≠ -1 && < cursor`), two seeded runs of 20,000 random inputs each (alphabet `* ** *** _ __ \ \* \\ \` `` \` a b space \n [ ] ( ) ~ = !`, length 1–60): **0 diffs** in `parse()` and in `parseInline()`. `parse(testing_markdown.md)` is identical too.
- G3 **D1 speed, same box, `"*a ".repeat(N)+"x"`.** N=5000: 1061 → 133 ms. N=10000 (30 KB): 7528 → 540 ms. After D1: N=20000 (60 KB) 2201 ms, N=80000 (240 KB) 32,932 ms. That is still quadratic, so 1 MiB is **estimated** at ~10 min (extrapolated, not run). `"_a "` N=20000: 2473 ms. One opener plus M escapes plus a closer (the per-iteration `indexOf(marker)` re-scan) gives 640 KB in 910 ms. D1 does not bound anything: D2's budget is load-bearing.
- G4 **Main-thread consumers D1 helps and D2 never touches.** `MessageRow.tsx:16` and `ReadOnlyBlock.tsx:30` call `renderInlineToReact`, which calls `parseInline(text)` on the main thread (`shortcutsReact.tsx:21`) on text written by *other members*. Before D1, a 30 KB message freezes every reader for 7.5 s (node 26); after D1, 0.54 s. This is a pre-existing cross-member availability bug. It is not in this plan's scope.
- G5 **F2 is blind to worker bundles.** Vite 6.4.2 `bundleWorkerEntry` runs a separate `rollup()` with `config.worker.plugins` and emits the worker's output through `saveEmitWorkerAsset` (`vite/dist/node/chunks/dep-Dq2t6Dq0.js:39991,40015`). `editorBoundary` keeps only `output.type === 'chunk'` (`vite.editor.config.ts:39`) and the config sets no `worker:` key. So "F2: 1080 modules, none banned" says nothing about the worker. A worker receives the local file's text and has `connect-src 'self'`, so it is exactly the surface F2 exists to guard.
- G6 **The CSP premise in the delta is wrong, but the outcome holds.** The editor CSP is `terminalCsp` (`static-client.mjs:57`), and that policy already carries `worker-src 'self' blob:` (`:51`). There is no fallback to script-src. A `/editor/assets/*.js` worker is allowed by `'self'`, and assets are served `text/javascript` + nosniff (`:20-31,84-94`). The current build emits `editor.worker-DysRFSaV.js` and loads it via `new Worker(""+new URL("editor.worker-…js",import.meta.url))` (`build/editor/assets/index-DuL1vfbY.js`). No CSP edit is needed, and EP4 holds.
- G7 **The AST is clone-safe by type.** `ast.ts` nodes are strings, numbers, booleans, arrays and nested nodes. No Map, Set, Date, class or function reaches the output (the only `new` calls in the parser are `new URL` in `linkMention.ts:45` / `urlSugar.ts:20`, read and discarded). `cleanArray` rebuilds every record as a plain object (`previewDocument.ts:47-51`). A `structuredClone(parse(testing_markdown.md))` round-trip is equal.
- G8 **But depth breaks the clone before it breaks the parse.** Node 26 default stack, F1-style nested list: depth ≤ **869** (763,740 chars) clones. Depth **870–1999 parses but `structuredClone` throws RangeError**, which is what `postMessage` would do. Today's main-thread code previews those documents. With `--stack-size=4000`, the EP5 fixture `"- ".repeat(5000)+"x\n"` *parses* (no RangeError), so the node:test `tooDeep` result is a property of node's stack, not of a Chromium worker's.
- G9 **Rung 2 (an existing worker client).** `MarkEngineWorker` (`packages/markdown-engine/src/worker-client.ts`) wraps a different parser (`src/block-parser` `parseMarkdown`, not `markdown/parser` `parse`). It parses synchronously on the main thread below 8 KiB (`:38`) and whenever no factory is given (`:248`), and it has no budget or terminate-and-recreate. It cannot be reused as-is, and extending it means a second submodule round-trip. An app-side client is acceptable once that rung is stated.
- G10 **Re-render cadence.** The preview debounce is 90 ms (`MarkdownPreviewSplit.tsx`, `PREVIEW_DEBOUNCE_MS`). In split mode every typing pause posts, so the supersede policy decides whether typing on a slow document livelocks or churns workers.

### Rulings on the questions

- **Is D1 safe?** Yes: G1 is a proof and G2 backs it. It is not a bound (G3), and the EP7 caveat must name emphasis runs as well as `[`. It is worth its submodule cost (one engine commit and push, `git ls-remote` proof, an osionos pin-bump commit), because G4 is reachable by other members today and D2 does nothing for it. D1 and D2 are independent: D2 must not wait for D1.
- **Is the worker design sound?** In outline, yes. The gaps are F2 (G5), the clone-depth path (G8), the undefined supersede and timer start (G10), stale-file display, and leak paths. All are conditioned below.
- **Is the structured clone safe?** By type, yes (G7). By depth, no (G8): the worker must catch its own `postMessage` failure.
- **Is 3000 ms right?** Yes. Normal 1 MiB parse is 34–48 ms (F3). Parse + clean + SSR at 1 MiB is 0.27–0.36 s, and that includes main-thread work the worker will not do. That leaves ≥ 8× headroom on this CPU and ≥ 2× on a 4× slower laptop. After D1, pathological input up to ~60 KB finishes inside the budget here. The cost of a long budget is only a later message, because the work is off the main thread. Condition: the timer starts when the request is posted to the worker that runs it (EP23).
- **Does D2 break anything in EP1–EP14?** EP8/F2 is broken (G5): EP20 fixes it. EP5's node test no longer proves the browser path (G8): EP21 + EP29. EP6's test must move from "parse once" to "post once" (EP25). The EP13 CSP premise is wrong but harmless (G6, EP29). EP1–EP3 hold only if the worker's cleaned output is the only thing ever rendered (EP22).
- **Must the app's .omd preview be fixed now?** No. It is pre-existing, opt-in (default `"code"`), self-opened, and not widened by this plan. D1 cuts it 8–14× (G3). File the issue (EP30).

### Alternatives considered (delta)

- **D2 without D1**: it bounds the preview but leaves G4 (other members' messages freezing readers at 7.5 s per 30 KB) at full cost. Rejected as a reason to drop D1; D1's cost is one submodule round-trip.
- **D1 without D2**: still quadratic (G3: 240 KB → 33 s), so the preview could freeze Monaco for minutes under the 1 MiB cap. Rejected.
- **Terminate and recreate the worker on every supersede**: on a document slower than the typing cadence (90 ms debounce), the preview never lands and a worker plus a module evaluation are spent per pause. Rejected for EP23's coalescing.
- **A main-thread fallback when Worker is unavailable**: it reintroduces the freeze D2 exists to remove. Rejected (EP22).
- **JSON-stringify the AST in the worker to dodge clone depth**: `JSON.stringify` recurses too, so it gets the same class of limit at a different depth. Rejected for catch-and-report (EP21).
