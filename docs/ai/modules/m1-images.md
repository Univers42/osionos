# M1 — Images: /imagine, on the local GPU

The slice of the school module IV.4 "complete LLM system interface" for images:
the user types `/imagine <description>`, an image block appears, made on our own
GPU (no paid service, $0 per image), stored through the bridge, marked
"AI-generated".

Everything here is bound to the conditions **C70–C78** of
`~/.cache/osionos-ai-records/a2-images-moderation-verdict.md`. The out-of-scope
of this slice is written at the bottom.

**Status: ai-dev only. The public stack stays OFF** (C70) until C72 L1 lands
(see "What is not done").

---

## What an evaluator does in three minutes

**1. Before the first start — the models (the only step with egress).**

In the groot worktree. The diffusion model and the VAE are pre-fetched into the
named volume `osionos_sd_models`; the engine itself never reaches the internet.

```sh
docker run --rm -v osionos_sd_models:/models curlimages/curl:8.11.1 sh -c '\
  B=https://huggingface.co/wbruna/Z-Image-Turbo-sdcpp-GGUF/resolve/ea7669b52d27042b4909e3413f58581c0d52d522; \
  curl -fL -o /models/z_image_turbo-Q4_0.gguf $B/z_image_turbo-Q4_0.gguf && \
  curl -fL -o /models/ae-f16.gguf $B/ae-f16.gguf'
```

The text encoder is the chat model's own cached Qwen3-4B file: the volume
`osionos_ai_models_llm`, filled by `osionos-ai-llm`'s first start. Nothing else
downloads.

**2. The stack.** `OSIONOS_AI_IMAGES=on docker compose --profile ai --profile ai-gpu-vulkan up -d` (groot worktree). The `ai-gpu-vulkan` profile needs `/dev/dri`: the engine reaches the GPU through it. The render and video group ids default to 993/44 and are set with `OSIONOS_AI_SD_RENDER_GID` / `OSIONOS_AI_SD_VIDEO_GID` — the host's own numbers, read with `stat -c %g /dev/dri/renderD128`.

**3. The image.** Open the app with `?osio.ai.images=1` (the client flag `osio.ai.images`, default OFF; or build with `VITE_OSIO_AI_IMAGES=1`), type `/imagine a lighthouse at dusk`, press Enter. A placeholder with "Generating image…" and a Stop button; then the 512×512 image with the caption "AI-generated" (hover: "Generated by z-image-turbo"). Reload: the caption stays.

**4. The prompt did not travel.** The stored file carries no trace of what was
asked for — see "What proves what", C77.

The smoke script (run from any container on the engine's network):

```js
// One image from the engine, twice (cold then warm): the seconds and the bytes' magic.
for (const run of ['cold', 'warm']) {
	const t0 = Date.now();
	const r = await fetch('http://osionos-ai-sd:1234/v1/images/generations', {
		method: 'POST', headers: { 'content-type': 'application/json' },
		body: JSON.stringify({ model: 'z-image-turbo', prompt: 'a lighthouse at dusk <sd_cpp_extra_args>{"seed":7}</sd_cpp_extra_args>', n: 1, size: '512x512', response_format: 'b64_json' }),
	});
	const j = await r.json();
	const b = Buffer.from(j.data?.[0]?.b64_json ?? '', 'base64');
	console.log(run, r.status, ((Date.now() - t0) / 1000).toFixed(1) + 's', b.length + 'B', b.subarray(1, 4).toString());
}
```

## What is not done

- **C72 L1 (a prompt classifier)** — the public stack stays off until it lands
  with tests. (C73 landed: the output check is in the service — see the
  caveats for what it does not prove.)
- **The cover picker's "Generate" tab** — the image is made from the editor's
  slash menu, not from the cover.
- **Regenerate and variations** — a second image is a second prompt.
- **Image-to-image** — a generation takes a prompt, never an image (C72).
  Images as *input* to a chat answer are their own slice (vision, C79–C82).
- **Paid image models through OpenRouter** — the local engine is the path.
- **Image models on a user's own key** — no user connection speaks to an image
  engine.

## Caveats

- **Caveat: the recall of the output check is UNMEASURED (C73)** — the gate is
  the union of two classifiers (Falconsai q8 at 0.5, AdamCodd q8 at 0.9), each
  at a threshold where it flagged none of the 352 safe images of A1, so the
  union costs no measured false positive; but no unsafe image was ever
  downloaded, generated or stored, so what the check CATCHES is unknown. A
  threshold without a recall is a proposal, not a number — the recall has to be
  measured on a licensed, labelled set before the thresholds are trusted.
- **Caveat: a check that cannot be loaded refuses every image (C73)** — the
  service still starts (the other routes are not hostage), and the image route
  answers `503 image_check_unavailable` until the models are on the disk.
- **Caveat: the Retry-After of `image_busy` is an estimate** — the runs ahead ×
  20 s (the warm time); a cold engine takes longer.
- **Caveat: a replica that dies holding the GPU turn blocks the queue** until
  its entry is older than a full wait plus a full generation (the `queue.ts`
  caveat), then it is pruned.
- **Caveat: every timing is ONE machine (RX 6600)** — another GPU, another
  number.
- **Caveat: the label is in the page, not in the file** — the stored PNG
  carries no provenance metadata (its text chunks are stripped, which is what
  keeps the prompt out); a downloaded image is not marked.
- **Caveat: the lineage is stated from the model card, not re-verified** — the
  GGUF is a third-party conversion trusted through its sha256 only.
- **Caveat: the rate-limit countdown in the editor is a static number of
  seconds**, not a live timer.
